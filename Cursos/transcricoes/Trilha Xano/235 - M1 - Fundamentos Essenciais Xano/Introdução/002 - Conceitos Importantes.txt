Então antes da gente continuar, vamos ver alguns conceitos importantes para você aprender sobre back-end antes da gente passar para o Zeno. Bom, é interessante que você entenda bem o que é um back-end. No nosso projeto de aplicativo, software, a gente sempre vai ter um front-end e... um back-end, tá? O front-end vai ser o lugar onde o seu usuário vai conseguir fazer toda a interação, a parte mais visual, a parte lógica, vai conseguir apertar nos botões. E aí sim, o back-end vai ser acionado, tá? E o back-end vai ter toda a parte de banco de dados, vai ter a parte de autenticação e segurança de usuários, também armazenamento, se a gente quer armazenar mídias ou PDFs, um back-end ele vai fazer isso. E também ações de servidor. Então a gente pode executar algumas ações e deixá-las agendadas no servidor. para elas acontecerem de tempos em tempos. Além disso, o Webhook, que aí a gente consegue fazer gatilhos para ser disparado alguma outra ação. Então, esse é um papel muito importante do back-end aqui para o nosso projeto. Muito legal. E no Flutter Flow, como é que funciona? A gente tem nossos back-ends integrados Low-Code, que são back-ends nativos do Flutter Flow, eles integram muito bem de uma forma nativa, que é o Firebase, que é no SQL, e o Superbase, que é em... em SQL. Tem cursos aqui sobre as duas ferramentas, também você pode depois explorar um pouco mais elas. E além disso, tem os backends no code, que o Xeno acaba sendo de longe o melhor backend no code da atualidade. Isso é bem positivo, porque os backends low code, eles podem exigir um pouco mais de conhecimento em programação, e às vezes pode ficar um pouco mais difícil a gente conseguir aprender. E os backends no code, como por exemplo o Zeno, é uma ferramenta muito poderosa, totalmente no code, que vai te dar uma curva de aprendizado muito mais rápida para você conseguir escalar o seu projeto. Então já adianto que esse daqui é o diferencial do Zeno. Além de você conseguir fazer um backend muito estruturado, você aprende rápido e consegue ter escala. E se a gente for falar de Bubble, o Bubble tem um grande diferencial que ele tem o frontend integrado com o seu backend. E nisso... é muito positivo para o Bubble, porque começa a ser bastante fácil a gente aprender dentro dessa ferramenta. Mas no Bubble, a gente também tem possibilidade de integrar com outros backends, como por exemplo o Supabase, ou também integrar com o Zeno, que acaba sendo uma excelente escolha, porque a união do Bubble mais o Zeno, você não fica preso só ao Bubble, e tem todo o seu backend lá atrás no Zeno, para ganhar muita performance e também maior escala. Então, acaba demorando bastante porque não é o objetivo do Bubble escalar tanto assim, né? Então aí você conecta com o Zeno e acaba tendo aí uma stack muito poderosa no code. E pra gente relembrar alguns pontos importantes, eu só quero relembrar pra você. O que são APIs? Se você já sabe, pode prosseguir. Mas a gente sempre gosta de explicar a API com base aí na analogia do restaurante, né? Vamos supor que o cliente, ele é o front-end e a cozinha é nosso back-end, né? O nosso server mais banco de dados. O API, ele vai fazer a comunicação entre o front-end e o back-end. Então ele vai levar uma informação, né? Se o cliente pedir uma comida, o garçom leva a informação de qual comida é pra cozinha, a cozinha faz. E o garçom retorna com esse pedido. Então o garçom ele nada mais é que o API. O API ele faz essa comunicação. E não só entre front e back-end do seu próprio projeto. Mas pode ser entre outros projetos também. Por exemplo, você pode ter uma API aberta. Como por exemplo o sistema de Booking. Então você consegue conectar o sistema de booking dos hotéis para pegar se tem reserva ou não tem reserva. Ou pode ter um API aberto de um sistema que vê o clima, né? Se ele fala se vai estar sol, quente, vai estar chovendo, você pode pegar e requisitar essa informação via API para esse sistema. E esse sistema ele te envia de volta. Então é isso que o API faz. Ele basicamente, ele comunica, ele leva e traz informação. E algo a se lembrar também é o CRUD, né? Que a gente tanto fala, que é a gente criar, conseguir ler. atualizar e deletar dados, né? Create, Read, Update e Delete. E o API também vai fazer isso com os métodos, tá? Vai ter, pra criar vai ter o post, pro Read vai ter o get, pegar informações, pro Update vai ter o put, então no API também vai ter isso, que é bem importante você saber pra gente conseguir continuar aqui no processo de aprendizado, porque basicamente no front-end e no back-end com Zeno, toda a comunicação vai ser feita por meio de API.
