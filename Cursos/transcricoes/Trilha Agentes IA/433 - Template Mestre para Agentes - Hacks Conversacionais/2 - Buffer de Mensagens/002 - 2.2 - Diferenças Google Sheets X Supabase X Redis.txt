Então, fazendo uma breve recapitulação aqui, a gente pode estar utilizando como base de dados, por exemplo, a gente vê muitas vezes pessoas utilizando o Google Sheets como um banco, uma... na forma de armazenar os seus dados. Não tem nada necessariamente de errado com isso, porém a gente sabe que a gente tem algumas limitações. Ele não possui algumas funções essenciais de banco de dados, ele tem uma baixa escalabilidade, a gente não consegue fazer muitas interações muito rápidas no banco de dados, o que pode gerar certos problemas. Então, ele é muito legal para a gente ter uma facilidade de uso, já fazer alguns testes, ter aplicações mais simplificadas, que não vai ter tanto volume de dados. Porque todo mundo sabe utilizar, tem uma interface muito amigável, a gente já está acostumado. Esse é o Google Sheets. A gente, em paralelo, tem um Supabase que por debaixo dos panos, o Supabase utiliza o Postgres como banco de dados. Então, Postgres, banco de dados, open source, extremamente escalável, robusto, utilizado amplamente no mercado. E o Supabase envelopa esse Postgres com muitas outras funcionalidades. O Supabase é um banco de back-end por completo. Então, o Superbase é um back-end altamente escalável, que usa o banco de dados Postgres, que é um banco de dados relacional, profissional, para a gente utilizar nas nossas aplicações. E aqui, de fato, o objetivo é a gente criar aplicações robustas que vão precisar de... um volume mais intenso de dados e, posteriormente, até questões de autentificação, se você quiser, porque o SpapBase tem mais funções para além também de um banco de dados. Claro que a gente poderia usar o Postgres nativamente, mas a gente gosta de usar o SpapBase aqui porque ele te dá toda uma interface mais amigável também, etc. E aí, por fim, a gente tem o Redis. Antes de falar do Redis... com um pouquinho sobre estrutura relacional de dados. Então, o Supabase utiliza o Postgres por trás, que é um banco de dados relacional. Quando a gente fala de banco de dados relacionais, a gente está falando que a gente consegue criar, de fato, relações entre as diversas tabelas que a gente tem. Isso utilizando algumas chaves identificadoras. Então, por exemplo, aqui, no meu cliente, eu tenho sempre o ID identificador do meu cliente. E aí, se eu tiver uma venda, essa venda tem que estar... associado a algum cliente. E para eu identificar o cliente, eu posso ter esse ID identificador dentro da minha venda. Eu não preciso replicar todas as campos lá do meu cliente, porque eu tenho que saber o RG do cliente, o nome, o CPF, o endereço dele, um monte de campos. Eu não vou replicar isso na minha tabela de vendas, eu só faço a identificação através do meu ID identificador. E isso vai se estendendo. Então, o pedido, aqui eu tenho o ID do pedido, o ID do livro. o ID identificador do pedido, o ID do livro, que é o livro que é uma outra base, que tem outros campos, e por aí vai. Então, essa é uma estrutura relacional de dados. E partindo para o nosso banco do Reds, que é um banco de cache, é um banco de parâmetro chave e valor. A gente sempre vai ter um valorzinho, uma chave, e essa chave, esse identificador dessa chave, vai ter ali um valor. Então, eu vou ter ali uma... um ID e esse ID vai ter um valor específico. Isso, cara, super padrão, né? São tabelinhas ali relacionais, de chave e valor simplificado, beleza? Então esse é o nosso banco de dados de cache, super rápido, ele é ideal aí pra gente fazer o uso de dados simples, chave e valor, não relacionais, é claro que dá pra fazer certas relações, mas não necessariamente relacionais. Dados, ele é excelente pra gente fazer... uso em dados temporários, dados que vão se expirar em um certo tempo, ele está trabalhando em cache velocidade também, e ele é muito bom para essa questão de trocas rápidas de dados. Então, para dados temporários, para dados que a gente quer fazer uma troca super rápida de dados, o Redis é, sem dúvidas, a melhor opção. E como a gente viu aí na nossa aula anterior, a gente viu que no nosso buffer, A gente quer armazenar ali rapidamente uma lista de informações e logo depois a gente vai estar deletando essa informação. Então, a gente quer que essa informação flua muito rápido. O Reds permite isso, porque o Reds está armazenado na memória. Um banco de dados postgres já está em disco. Algumas coisas um pouco mais técnicas, mas não vem tanto ao caso aqui. Saber que o Reds é super rápido para isso e excelente para essa questão de tratamento de dados temporários. E só evidenciando isso um pouco de chave de valor para não ficar... Putz, muito complexo. Nada mais é do que, cara, tem uma chave, que é ali um ID, e esse ID vai ter um valor, vai ser o ABCD. Aí eu tenho outro ID, né? E aí vou ter esse valor. A gente já veio vendo isso aí quando a gente está utilizando a memória ali dentro do nosso agente. A gente vai lá e coloca o ID identificador da nossa memória e do lado a gente vai adicionando ali os valores para isso. Não é algo similar a isso daqui. Beleza, pessoal?
