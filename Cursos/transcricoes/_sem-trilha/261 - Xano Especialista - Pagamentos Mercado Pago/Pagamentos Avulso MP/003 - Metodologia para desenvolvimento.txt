Então, o nosso primeiro passo antes de iniciar qualquer desenvolvimento de aplicação é definir qual é o problema que nós queremos resolver com essa aplicação. Então, não adianta colocar a mão na massa e começar a sair desenvolvendo sem antes saber o que problema nós queremos resolver. E para ajudar a entender melhor, nós vamos utilizar uma metodologia... que vocês já conhecem, já viram bastante aqui na NoCode Startup, que é a metodologia NoCode Startup, onde a gente passa a entender qual é o problema, a gente traz ali qual é a solução que a gente quer implementar, a gente trabalha com o design de telas, mas é importante relembrar, nós não vamos trabalhar com design de telas. A nossa intenção é criar um micro serviço de pagamento para que você possa utilizar o front-end que desejar. Em seguida, vamos para o banco de dados e depois partimos para o desenvolvimento. E qual é o problema apresentado? Vamos apresentar para vocês o e-commerce da BR3D. A BR3D Soluções é uma startup que desenvolve produtos impressos em 3D. Então, eles atendem o mercado de decoração, arquitetura e prototipagem. E eles querem alterar o meio de pagamento que eles utilizam hoje para o mercado pago. E é aí que a gente entra. A solução que a gente definiu foi que, depois que o cliente selecionou o meio de pagamento do mercado pago, vai ter um botão pagar com o mercado pago. Ao clicar nesse botão, o comprador será direcionado para uma página do mercado pago, para efetuar o pagamento. Porém, por trás, vamos chamar uma aplicação que foi desenvolvida, que será desenvolvida em Zano, para em seguida fazer todas as operações dentro do mercado pago. criar todas as preferências necessárias, fazer todas as consultas e validações que precisamos para garantir que o pagamento foi efetuado e se não foi, ter essa certeza. Então, voltando um pouco para a metodologia no Code Startup, nós já havíamos definido o problema, problema simples, vamos só fazer a chamada do Mercado Pago para disponibilizar o meio de pagamento para o comprador. A solução vai ser essa integração via Zano, onde após essa chamada, será chamada uma API do Zana e o Zana vai fazer as operações dentro do mercado pago. Depois, iniciaremos a estruturação do banco de dados, fazendo toda a parte de análise de requisitos, modelos conscentuais, modelos lógicos e, em seguida, os modelos físicos.
