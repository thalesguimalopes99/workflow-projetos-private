Então, de volta ao Zano, nós vamos diretamente para o nosso banco de dados. Vamos criar uma nova tabela. Então, vamos clicar em Add Table e vamos dar o nome de assinaturas. Não vamos criar os endpoints agora. A gente vai criar todos os endpoints manualmente. Vamos clicar no botão Add Table e vamos adicionar a nossa tabela. Então, assinaturas. E vamos remover o Add Basic Crude Endpoints. Nós vamos criar todos os nossos endpoints relacionados à assinatura manualmente depois. Então, vamos dar um remover e adicionar tabela. Agora, a gente vai adicionar as colunas que a gente quer para a nossa tabela. Então, a primeira que a gente vai adicionar é uma tabela de referência com a nossa tabela clientes. Em seguida, vamos adicionar uma nova tabela referência. com a nossa pedidos. Aí vamos também já criar uma tabela referências com a nossa pedidos, pagamentos, mercado pago. Aí podemos criar uma coluna do tipo texto para a gente colocar o ID da assinatura. MPassinaturaID. Vamos clicar no botão salvar. O próximo que a gente pode adicionar também é de texto, que é a descrição da assinatura. Salvar. O valor total da assinatura, então é um valor, vamos colocar como decimal, valor total. Aí a gente clica no botão salvar, vamos adicionar um número inteiro do tipo frequência, qual que vai ser a frequência desse pagamento. Vamos adicionar uma nova coluna chamado tipo de frequência. E esse tipo de frequência vai ser do tipo enum. Porque como a gente viu já na documentação, vai poder ser por dias ou mês. Então, vamos criar aqui tipo frequência. E a gente vai adicionar dia e mês. Podemos salvar. Em seguida, podemos trabalhar ali com as datas. Data início e a data fim. Vamos adicionar uma nova coluna. que é do nosso init point. Então, é do tipo texto, init point. E, por último, o nosso status, que também pode ser um enum. Então, a nossa assinatura pode estar pendente, status. E em valores, a gente pode estar colocando pendente, autorizado e cancelado. Vamos entender que a assinatura já nasce pendente, então a gente utiliza, vai ser a nossa padrão, toda assinatura nasce pendente. E aí depois que houver o pagamento, ele pode estar ali autorizado e por hora a gente vai trabalhar com cancelado. Vamos cancelar uma assinatura durante essa jornada. Então vamos trabalhar justamente com esses três status. Com esse modelo... A nossa tabela de assinaturas já está criada. Então, podemos seguir ali com o desenvolvimento da nossa API para coletar as informações da API e já salvar dentro do nosso banco. Para a gente passar a ter a gestão ali da nossa assinatura, saber se ela foi paga, atualizar, pegar atualizações sobre aquela assinatura. Então, a partir de agora, a gente começa a salvar as informações no banco. Bora lá!
