Agora vamos para o último assunto bem importante conectado com a API, que é sobre o webhook. Vamos entender o que é um webhook. Então quando a gente está falando de API, a gente tem o nosso exemplo do restaurante, que o cliente faz o pedido, então a API leva o pedido e a cozinha faz o prato, a API volta com o prato. Então na API sempre tem esse fluxo de ir e voltar, vai com a nossa requisição e volta com a nossa resposta. Esse daqui é um padrão de API. Para o Webhooks é um pouquinho diferente. No Webhooks a resposta vem de uma forma automática da cozinha. Por exemplo, vamos supor que a cozinha já vai avisar o cliente quando o pedido for terminado. Então, o pedido está preparado, a cozinha vai lá e já avisa o cliente. Então, a diferença de Webhook é que não precisa de uma requisição. Ele vai ficar esperando algo, um gatilho para tomar alguma ação e vai vir direto. Para ficar mais claro, a gente tem aqui as APIs que a gente pergunta se precisa de um novo os dados. e aqui dá os dados de volta aqui em WebRupt esses dados já são enviados sem a gente precisar tá? A gente geralmente vai ficar esperando e aí esse dado vai ser enviado a partir de determinado gatilho tá? Para você entender um pouco mais sobre exemplos práticos um exemplo bem legal que a gente tem é quando a gente tem um software né? Um SaaS a gente quer colocar um modelo de assinatura então ao invés de pegar e falar e perguntar lá por nossa integração né? Que a gente pode integrar assinatura com pagarme com o Mercado Pago, com o Stripe, com asas, para essas ferramentas controlarem a assinatura dos meus usuários, eu poderia falar assim, né? Por favor, quero saber se esse usuário aqui pagou a assinatura dele desse mês. Aí pergunta. Aí, por exemplo, o Stripe vai falar, esse cara aqui pagou a assinatura do mês. Aí volta, retorno. E aí eu vou liberar o meu site, o meu software para ele naquele mês. Então, para eu não ficar perguntando sempre, porque senão seria bem trabalhoso, a gente usa um webhook. Então o que o WebHook vai fazer? O Stripe vai ficar ali olhando se o usuário pagou aquela assinatura. Então ele vai ficar de olho quando der o vencimento dele. Se ele não pagou a assinatura ou se ele pagou, ele vai retornar esse aviso para mim de uma forma automática. Eu não vou precisar pedir para ele. Então eu vou ficar esperando quando chegar no dia de pagamento. O Stripe vai falar, ó, esse usuário pagou. Pode deixar o software para ele. Se não pagou, eu vou ficar esperando. E aí vai vir aquela informação que o usuário não pagou e eu vou tirar. assinatura dele. Então por isso que é importante o Webhooks pra gente conseguir ficar esperando informações e não precisar ficar sempre perguntando, tá? Geralmente em pagamentos a gente vai usar bastante o Webhooks. Então espero que tenha ficado claro toda essa parte de APIs, da estrutura de API e de Webhooks porque é muito importante a gente vai usar bastante lá no desenvolvimento das nossas soluções.
