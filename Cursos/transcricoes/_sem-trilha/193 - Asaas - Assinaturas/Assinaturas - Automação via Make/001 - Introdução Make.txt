Agora que você já entendeu como funciona o checkout transparente e já criou sua assinatura para o seu usuário, a gente pode entender como vai funcionar agora o gerenciamento dessa assinatura utilizando o Make, que é o nosso aplicativo para automações. Antes da gente conhecer o Make, eu vou mostrar para vocês qual é a diferença entre o Webhook e uma chamada API, que é a diferença entre Pulling e Pushing. São verbos no inglês que todo mundo deve conhecer, mas para quem não conhece... Você fazer o pooling é você enviar e receber uma informação da sua chamada API. É o que a gente está fazendo quando eu crio uma cobrança, quando eu crio um customer e tudo mais. Isso não é recomendado de você ficar fazendo toda hora, ou por exemplo, toda vez que algum usuário faz o login. E, como vocês devem imaginar, para eu gerenciar uma assinatura, eu preciso que toda vez que o usuário faça o login, ele verifique se o pagamento foi feito ou não. Quando a gente usa uma chamada API para verificar isso, acaba forçando muito, fazendo muito pooling. E isso não é bom para o desempenho do seu aplicativo. E você pode até acabar sendo bloqueado pelo Asas se você ficar fazendo esse tipo de pooling de diversas vezes no dia ou na semana. Por exemplo, se você tiver, sei lá, 10 mil usuários dentro do seu aplicativo, se todos eles entrarem e fazerem chamada de pooling toda vez, não vai ser muito bom e você provavelmente vai ser bloqueado. Então, é aí que entra o Pushing, que é onde você apenas vai receber uma informação a partir de um webhook, que é um link que está vinculado a algum gatilho, se alguma coisa acontecer relacionada àquele gatilho. Então, por exemplo, a gente tem aqui um exemplo de API, onde eu pergunto para a API qual é o status da assinatura daquele usuário e ela vai me responder com o status de desativado. Beleza. No Webhook é ao contrário, eu não preciso perguntar, ele simplesmente vai me enviar uma informação a partir do momento que a assinatura do usuário mudar de ativo para desativado. E está tudo bem, agora eu tenho essa informação, que é aquela assinatura daquele usuário, ela não está mais ativa. E isso de forma automática, eu não precisei de perguntar, ele simplesmente, aconteceu aquele gatilho, durante aquele mês o pagamento não foi efetuado, e ele vai me falar, não foi pago, então é porque... a assinatura também vai ser desativada. E como vai funcionar, galera? A lógica da automação dentro do Make. É muito importante vocês entenderem isso aqui primeiro, porque quando chegar no Make, a gente vai estar configurando tudo isso, mas essa é a lógica. Primeiro a gente vai ter o gatilho, que é o Webhook, onde ele vai falar alguma coisa. Aconteceu uma cobrança, a cobrança foi gerada para aquela assinatura naquele mês. Beleza, eu vou ter várias informações dentro desse primeiro Webhook. Aí eu vou perguntar para o meu banco de dados do Firebase, existe alguma assinatura já criada com esse valor de sub... o valor dela ali. Se sim, eu tenho uma variável para atualizar aquele documento que já existe. Se não, eu vou criar uma nova assinatura, um documento de assinatura no meu banco de dados. Tá bom? Então, isso é claro, a gente vai ter uma verificação aí apenas no momento em que o pagamento ele for feito com sucesso ou não, tá bom? Então, se não for feito com sucesso, ele nem vai ser avançado aí na parte de verificação se existe ou não a assinatura, ok? Então, agora que você já entendeu como que funciona, como que vai ser estruturada aí a nossa automação, vamos explorar o Make e vamos criar a nossa automação aí juntando o Make, o Flutter Flow e o Firebase. Espero que você esteja animado. Se você já conhece, já fez a parte do Stripe, você vai estar bem familiarizado. Mas se não conhece, é a primeira vez que você está tendo contato com o Make. Preste bastante atenção, porque é uma ferramenta que é muito poderosa, é muito legal de trabalhar. Mas ela é muito delicada, os detalhes são muito importantes dentro da ferramenta, tá bom? Então vamos colocar a mão na massa, bora lá!
