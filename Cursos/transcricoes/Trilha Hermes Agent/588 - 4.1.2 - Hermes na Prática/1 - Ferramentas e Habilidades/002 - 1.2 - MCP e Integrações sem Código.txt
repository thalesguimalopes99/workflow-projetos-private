Então vamos lá para a nossa aula 2.2, vou passar aqui para vocês agora o que é esse tal de conceito de MCP. Você já deve ter visto isso lá na aula do OpenCloud novamente, nas aulas de Cloud Code, caso você não saiba o que é esse Model Context Protocol, protocolo de contexto para o modelo, no caso, e essas integrações sem código, sem precisar conectar, ler uma documentação inteira, graças ao MCP a gente tem... várias conexões ali, damos mais inteligência, mais ferramentas para o nosso agente, para o nosso modelo aqui. Mas quero fazer para vocês entenderem antes e depois do MCP. Antes do MCP, a gente tinha as APIs exclusivas para cada coisa, para cada ferramenta que a gente quer conectar ali. Então, a gente tem uma API do Slack, tem uma API do Google Drive e tem uma API do GitHub aqui de exemplo. Só que essas APIs, elas têm vários endpoints que a gente chama, vários pontos de acesso que a gente vai fazer tal ação. Então, a gente tem um endpoint lá para ler um arquivo dentro do Google Drive. A gente vai ter um outro endpoint para deletar um arquivo. Vai ter um outro endpoint para mover um arquivo. A gente vai ter um outro endpoint para criar um arquivo também. Então, a gente tem vários endpoints ali criando, sendo várias atividades, vamos chamar assim. que isso, imagina isso se criando várias conexões de APIs ali com o seu agente, isso vai ficando enorme. Pense isso daqui, que aqui vai abrindo uma ramificação um pouco maior aqui para baixo, daí aqui mais uma ramificação maior aqui, outra ramificação, então vai ficando tipo um organograma enorme. E daí o teu agente tinha que ficar adivinhando aonde ele tem que ir para chamar, fazer aquela ação que você solicitou naquela tarefa. Depois, com o MCP, o que aconteceu aqui agora? Eu gosto de usar a analogia de um pendrive. Você tem um pendrivezinho lá, que dentro desse pendrive você tem várias pastas, certo? Várias pastinhas. As pastinhas são aqui, Slack, Google Drive e GitHub. Só que dentro dessas pastas tem seus arquivos lá dentro. Tem várias... fotos ali, vamos usar de exemplo ali dentro. Então tem a pasta do Slack com várias fotos ali, vários arquivos lá dentro, o Google Drive também tem a pasta do Google Drive, vários arquivos que são os endpoints, aqui no caso, e do GitHub a mesma coisa. Você pede uma tarefa ali para o seu agente, para o seu Cloud Code, Codex, Hermes, OpenCloud, você pede para ele, ele vai acessar o MCP, cada... fotinho, vamos dizer, cada arquivo desse aqui tem uma pequena descrição para o seu agente. Então, quando você pede para ele e fala, cara, eu preciso que você encontre no meu Google Drive um arquivo assim, assim, assado e mova ele dessa pasta para outra pasta. Cara, ele vai saber que ele tem que acessar esse pendrive, esse MCP do... Google Drive. Ele vai ler as descrições dos endpoints, do que tem que ser feito. Então, ele vai falar assim, eu tenho que procurar um arquivo assim, assim, assado. Então, ele vai fazer um search. Depois desse search, eu vou ter que entrar em outro arquivo, em outro endpoint aqui, para mover ele de uma pasta para outra pasta. Então, ele também tem que achar essa pasta, essa segunda pasta. Então, ele fez tudo isso muito rápido. Ele vai acessar tal, tal e já move o arquivo para você. Mesma coisa ali também, o do... No Slack também, né? Então, tem todas as suas atividades que ele tem que fazer. Ah, eu vou ler uma mensagem, vou executar uma ação ali de enviar uma mensagem, deletar um arquivo, adicionar uma nova pessoa aqui dentro do nosso ambiente do Slack. Então, o legal é que o MCP, ele te deixa mais organizado, te deixa mais unificado. E para uma integração é muito mais rápido para você fazer. Às vezes é só pegar uma chave API e pedir para ele, ó, instala para mim esse MCP, aqui está aqui a chave API para você fazer a conexão. Então, isso adianta e muito, e te dá uma inteligência muito maior para o seu modelo, para o seu agente aqui, no caso. E como que funciona, pessoal? Você pode simplesmente... pedir para ele falar cara eu tenho esse mcp aqui você pode pegar o link da página do mcp e falar cara vamos conectar esse mcp do notion aqui é vamos criar o mcp do google gmail cheats calendar aqui do github bancos e tudo mais então ele consegue acessar e todos os seus bancos e dados acessar seu notion mas o que a gente consegue fazer aqui também né um agendamento no google calendar por exemplo então verificar todo o seu calendário ali, marcar, desmarcar reuniões, criar uma nova página no Notion também, é o que eu faço que muito no meu dia a dia, eu tenho meu Notion conectado no meu Cloud Code, eu tenho meu Notion conectado no meu Hermes, então às vezes eu estou fazendo alguma coisa, peço para ele criar uma página no meu Notion, depois estou na rua, peço para ele acessar aquele meu Notion, o Hermes peço para ele acessar o meu Notion, para ele verificar aquele relatório, ou até pegar aquele relatório para eu mandar para um cliente, então eu uso muito o Notion no dia a dia. criar issue do repositório, correções no GitHub graças ao MCP, atualizar planilhas, dados em tempo real, acessar banco de dados.
