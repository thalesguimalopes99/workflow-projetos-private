Isso é importante, porque vai te ajudar até a entender, poxa, será que sou eu que estou errando? Será que o problema é lá no servidor? Essas perguntas eu tenho certeza que você já se fez, porque muitas das vezes não é erro. Seu, não é erro ali do front-end na programação. Às vezes é um erro temporário, às vezes é um erro do servidor. Então a gente precisa entender esses códigos para tratar, para poder tomar as ações devidas. Então vamos aqui para o nosso projeto. Nós temos aqui o nosso projeto aulas, tá? E eu vou deixar aberto ele aqui, aqui na nossa pastinha aqui de logs. E eu tenho aqui uma coleção de erros que eu vou deixar na descrição dessa aula e vamos procurar entender aqui os tipos de erros. Nós temos aqui os mais comuns, que são da categoria 200, da categoria 400 e da categoria 500. Mas para ser bem abrangente aqui e você entender... Você sabia que nós temos erros que começam com 100? Normalmente, os 100 estão em cenários um pouquinho fora do Superbase, mas você pode encontrar aí, às vezes, e se você encontrar uma resposta 100, não se preocupe. É apenas ali uma transição de comunicação de servidores, de proxies e tudo mais. Quando você tiver um sucesso, sempre vai ter o 200, ou seja, 200, 201, 204, sempre vai estar relacionado ao sucesso. O 201 são as respostas gate, post, patch, delete, ali quando você obtém o sucesso de uma chamada. O 201 é quando você faz uma criação de alguma coisa, por exemplo, você criou um registro, criou um... enviou um arquivo lá para o storage, fez um upload de dados para o seu back-end. E o 204 é quando você deletou ou fez alguma alteração ali e não teve nenhum retorno. Então agora fica claro, às vezes você se pergunta, mas por que deu 201 ou 204? Então é por conta desta nomenclatura e desta termologia. O 300, Ele é raro também, mas você vai encontrar em movimentação de dados, ou seja, dados temporários, moveu, fez integração com uma outra plataforma terceira, normalmente vai vir aí a resposta 300, ok? E o mais utilizado e o mais útil aqui para nós no debug de erros, ele está na categoria aqui do 400. Então, vamos escorrer aqui. Olha só, quando você tiver uma bad request, que é o que eu acabei de fazer ali, o que pode ser essa bad request? Pode ser payload JSON mal formado. O que é payload JSON? Você mandou dados JSON para incluir em alguma tabela e está mal formada. Vai dar eu 400, uma bad request. Ou, igual eu fiz na aula anterior, um login errado de usuário. vai dar erro 400. Ou uma requisição sem os parâmetros obrigatórios de ad functions, vai dar erro 400. O 401, quando, por exemplo, uma tentativa de acesso numa tabela com RLS inválida. Então, vamos imaginar que teve ali uma chamada com políticas de segurança que não estão satisfatórias para determinado usuário. Ou um token, um JW token expirado, vencido, ou uma ad functions que não está protegida sem o token. Aí vai dar 401. Quando for 403, é uma tentativa de acesso a recursos não permitidos, também com políticas de RLS e mesmo com token válido. Por exemplo, aqui olha só. Aqui a gente tem políticas de RLS. Quando for 401, eu tenho tentativas de acesso a uma tabela com RLS sem o JW token ou com token inválido. E aqui, olha só, o 403 eu estou com token válido. Mas mesmo assim eu não consegui acesso àquela tabela. O que o 403 está dizendo para a gente aqui? Olha, amigão, você tem o token. Você está logado, mas você tem acesso aqui a várias tabelas, mas nessa tabela em específico você não está podendo acessar, porque você não tem dentro lá das RLS, você que já estudou ali as políticas de segurança, lembra? Você não tem permissão de RLS para acessar os dados dessa tabela. Percebe que fica fácil desse jeito? Quando você sabe exatamente o erro, Você vai lá, ah, 403, significa que eu tenho o token válido, mas eu não tenho a permissão para acessar determinada tabela. Então vamos seguir aqui. Eu estou aqui agora no 404. Eu tenho uma tentativa para acessar uma view ou uma tabela que não existe, ou o endpoint é inexistente. 404, isso aqui é muito comum. Às vezes você está ali batendo cabeça. tentando acessar um endpoint e vai receber uma resposta 404. E se você não souber exatamente o que o 404 está te falando, você vai perder muito tempo até encontrar, poxa, às vezes é uma vírgula, às vezes é uma letra que está no meio do endpoint que quebra as pernas. E o 405, exatamente para add functions. Então, quando você faz um get, E só aceita post. Isso é muito comum também. De repente você tem ali uma função. Que só vai aceitar post. Mas você está mandando o get para ela. E aí o 405 vai te orientar. Olha. Veja o cabeçalho da sua chamada. Que você precisa arrumar. Não é o método get. É o método post. E quando for tentativa de insert. Com um e-mail que já existe. Está violando ali alguma regra. de unique. O que é unique? Quando tem uma constraint, o que é uma constraint? Tem uma regra lá dentro que só permite um e-mail único dentro de uma determinada tabela. Ele vai dar um erro de 409, vai dar um conflito. E, por fim, aqui, nós temos aqui o 429, quando tiver excesso de requisições API, ou seja, muitas requisições ao mesmo tempo e... O superbeis ali não deu conta, ele vai dar. É raro ver isso aqui, mas acontece também, tá? Então, essa aqui é a família maior que nós temos, é a família do 400, né? E é tão importante você decifrar esse erro aqui da família do 400, tá? E agora, vamos aqui para a família do 500. Por que que eu até comentei no início dessa aula aqui? Às vezes o erro não está com você. Então todas as vezes que você ver assim uma chamada com resposta 500, significa que aquela resposta de 500 aconteceu alguma coisa lá no servidor. Por exemplo, a chamada 500, eu tenho um erro interno na minha função de borda. Pode ser um erro ali que está nos servidores daquela localização. Um erro de autenticação interna durante o processo de autenticação pode acontecer de cair em uma fração de segundo, cair ali a conectividade e dar um erro ali, 500. Uma bad request pode ocorrer em problemas de infraestrutura do Supabase. Então aqui, olha, 502, se tiver algum problema de infraestrutura, Isso é raro também, mas acontece. Você pode estar tendo uma resposta 502, você já tem certeza, poxa, está tendo algum problema lá de infraestrutura. E a 503 pode ocorrer durante manutenção do programa Supabase, picos de tráficos, banco de dados temporariamente indisponível. Então, essas categorias de erro aqui, você percebe que não está na sua mão resolver, você tem que ter ali... A sabedoria tem que ter o conhecimento, poxa, estou tendo uma resposta 500, agora eu sei que o 500 é uma coisa, o 502 é outra, o 503 é um problema temporário do Superbase e eu vou poder analisar e dar a resposta com coerência para quem quer que seja, até mesmo para você mesmo, para você tomar a decisão mais correta possível.
