Antes de conhecer o que é exatamente o Supabase e a sua arquitetura e a história por trás dessa ferramenta maravilhosa, vamos entender aí o conceito, o conceito de banco de dados e back-end tradicional. Até... Nos anos 2000, 1999, as aplicações normalmente eram ali dentro de uma rede fechada, num desktop, e os dados, o famoso banco de dados, eram armazenados localmente, numa rede local. Então a gente conhecia o Axis, o Debase, o Oracle, o Microsoft SQL. E com o surgimento das aplicações web, da internet, Esse conceito de banco de dados começou a mudar de nome. Ele começou a receber o nome de back-end. E o que eu estou chamando aqui é um back-end tradicional. Então, de 2000 até 2014, o back-end, eu parei aqui no 2014 porque ainda tem mais história. Mas o que é o back-end? É um serviço que ocorre lá do lado do servidor. Ele lida com as lógicas de negócio. gerencia os dados, autenticação, notificações, real-time, tá? Então, tudo aquilo que o usuário, que não está visível ali para o usuário, diretamente, a gente denomina como back-end, tá? E o usuário que está ali na frente da interface da aplicação, ele só vê o resultado do que é gerado, do que é processado lá pelo nosso back-end. E esse back-end... ele era um serviço, ainda são os back-ends tradicionais, eles são um serviço muito complexo de ser implementado. Então, através de uma lacuna de mercado, de uma oportunidade ali que é o grau de dificuldade técnico elevado para fazer as implementações, surgiram desde 2014. também com o crescimento das aplicações web e mobile, os back-end as a service, a famosa sigla BAS. Se você não sabe o que é um BAS, é uma analogia ali ao SaaS, que é o software as a service, no caso do back-end é um back-end as a service. E os pioneiros, teve... Um pioneiro que não existe mais, que era do Facebook, mas um dos pioneiros em 2014, o Firebase. Ele veio com uma proposta para melhorar essa questão de dificuldade de implementação, simplificar o processo ali, porque para implementar um back-end tradicional, o desenvolvedor tinha que lançar a mão de muitas coisas ter um autoconhecimento técnico para implementar uma aplicação. E o Firebase, ele simplificou esse processo. Só que o Firebase, ele veio brigar com uma cultura de 40 anos de SQL e banco de dados relacionais. Então, ele trouxe um termo. É a primeira vez que surgiu o termo em NoSQL. De uma certa forma, ele fragmentou os dados em tabelas e... E esses dados não tinham relacionamento, não eram processados via SQL. E com isso, uma pessoa chamada Paul Colpestone, ele é cofundador do Supabase, em 2020 ele tentou usar o Firebase, só que ele teve muita dificuldade. Então ele percebeu uma lacuna de mercado. Então ele trouxe aí para nós, para a nossa grata surpresa, para eu que sou um fã de Supabase, uma ferramenta capaz de concorrer com o Firebase, só que alinhado aí à cultura, alinhado aos 40 anos de SQL e banco de dados relacional. Então ele utilizou ali o PostgreSQL, então esse desenvolvedor aproveitou Olha só que legal, ele aproveitou uma lacuna de mercado e criou um negócio, um negócio que hoje é milionário. Então é muito interessante a gente conhecer a história, conhecer os conceitos. Então agora a gente é capaz de responder o que é o Supabase. O Supabase é um BAS, um Backend Asa Service. E ele está lá fazendo a sua função de Backend. para que os usuários finais das nossas aplicações possam utilizar as suas aplicações de forma fluida. Por quê? Porque o back-end Supabase utiliza banco de dados relacional, um banco de dados poderoso, que é o PostgreSQL. Então, o que a gente tem que entender aqui? Que ele é muito mais que armazenar dados. O Supabase e a sua arquitetura em comparação com as outras ferramentas. Eu trouxe aqui um breve comparativo. Por exemplo, nós podemos agrupar armazenar dados em planilhas, sim. Ela é fácil de configuração, sim. Ela tem uma interface amigável, sim. Só que as demais funcionalidades não têm. Relacionamento formal entre tabelas, consultas complexas em SQL. API, autenticação de usuários, segurança granular, armazenamento de arquivos, eventos em tempo real e escalabilidade. E os bancos de dados tradicionais que são ali a base, na verdade, os back-ends tradicionais que são a base desse ecossistema, como eu comentei, eles têm uma dificuldade enorme para fazer as demais... funções de um back-end com relação à implementação e manutenção. E o Firebase, por sua vez, ele não é um banco de dados relacional, não tem relacionamento entre tabelas, e para a implementação de consultas é bem complexo. E por conta disso, a sua escalabilidade se torna um desafio. Não que não seja possível, mas para escalar uma ferramenta, Feita com o Firebase, você já tem que estar ciente que lá na frente, se você quiser gerar consultas complexas que vai exigir um grau de relacionamento entre as tabelas, você vai enfrentar um bom desafio. E o Supabase, para a nossa alegria, ele cobre todas essas lacunas. Por isso que o Supabase está ali no cerne do NoCode, do VibeCode, do NoCode, de automações N8N.
