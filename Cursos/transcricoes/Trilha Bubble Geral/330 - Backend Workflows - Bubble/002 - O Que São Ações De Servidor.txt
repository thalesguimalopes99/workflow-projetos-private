Fala aí, turma! Sejam bem-vindos para mais uma aula. E nessa aula eu vou estar explicando para vocês o que são ações de servidor, tá? Como já falei em alguns vídeos anteriores, as ações de servidores ocorrem na nuvem, tá? Independente da máquina do usuário, ok? Ela não precisa estar com o computador aberto ou a página aberta no celular. Ela vai ocorrer na nuvem, independente do usuário estar com o aplicativo aberto ou não, tá? Tendo isso em vista, algumas ações principais que ocorrem no servidor... é o armazenamento de dados, onde ele pode salvar esses dados, criar ali no banco de dados, vai criar e vai salvar no banco de dados. Tem as ações de recuperação de dados também, que é uma consulta. Por exemplo, ali no caso do Bubble, a gente tem, poderia ser um GET, mas no caso do Bubble, a gente utiliza o Sexto Fora ali no banco de dados diretamente. Então, por exemplo, se você estiver utilizando um banco de dados externo, você vai utilizar um API Flow ali e vai criar um GET para puxar do banco de dados externo. a lista dos dados que você precisa. Então, isso é a recuperação de dados, tá? Você vai buscar os dados que você precisa com base em filtros e parâmetros ali através da URL. Processamento de dados, tá? Os processamentos de dados são cálculos, transformações, que nem eu já fiz ali um exemplo pra vocês. A transformação é quando você envia alguma alteração ou tem uma alteração agendada e ele altera um dado automaticamente lá no banco de dados. Por exemplo, pode ser um status, uma data ou um checkbox, por exemplo. A autenticação do usuário. Verifica se o usuário tem uma conta, se ele não tiver uma conta ele cria, ou até mesmo se ele tem acesso, se ele tem acesso permitido àquele sistema. Isso também pode ocorrer no back-end, ao invés de utilizar o front-end. Uma outra ação também bem conhecida é autenticar o usuário. Verificar se ele já tem uma conta e realizar o login no sistema, ou até mesmo criar uma nova conta para o usuário, ou verificar se ele tem realmente acesso à conta. se ele está com a conta ativa ou não. Essa verificação pode ocorrer também no back-end. Seria a forma mais segura, na verdade, de você realizar essa verificação. Uma outra ação também que é utilizada no servidor é a regra de negócio, a regra do seu aplicativo. Digamos que você tenha um SaaS, um aplicativo que é multi-empresa. Nesse aplicativo, você vai definir que todos os dados da empresa, somente o usuário que é vinculado a essa empresa vai visualizar. Então, é basicamente uma regra de visualização, tá? Uma regra de negócio. Todos os usuários daquela empresa podem visualizar os dados dessa empresa e assim consecutivamente. Ou seja, podem interagir entre os mesmos usuários da empresa, podem criar dados dentro daquela empresa e nada além das outras, ok? Isso seria uma regra.
