Então pessoal, nessa aula eu quero aprofundar um pouquinho com vocês sobre as questões de assinatura e também já comentar um pouquinho sobre a Herbhooks. Sei que para muitos aí o objetivo de vocês aqui nessa trilha é aprender como fazer uma assinatura, como utilizar uma assinatura para implementar no aplicativo de vocês e cobrar uma mensalidade pelo uso desse app. Então analogamente aqui na loja virtual que o João tinha, agora ele não tem mais uma loja virtual, ele está criando ele, tem um aplicativo SaaS, que ele quer... cobrar uma mensalidade dos seus usuários. Então, analogamente à loja virtual, ele também precisa fazer o uso de gateways de pagamento que permitem essa ação de assinatura. Não são todos os gateways. Hoje, a maioria deles já permite essa ação de assinatura, mas não são necessariamente todos. Então, aqui o primeiro comentário que eu tenho a dizer é que... Questões de assinatura, quem vai gerir os cartões? A gente nunca armazena cartões dentro do nosso aplicativo. A gente até pode, porém não é nada recomendado. Então a gente deixa todo esse trabalho de segurança, armazenar dados de cartão, armazenar senha lá com os gates de pagamento. Eles têm toda a estrutura para isso. Eles que vão gerir e dizer quando ele tem que cobrar um outro cartão, qual cartão cobrar, e aí o usuário não precisa nem colocar os dados novamente. Então, por isso que o gateway de pagamento tem que oferecer já essa função de assinatura para que a gente consiga utilizar e implementar no nosso app. Novamente, eles são integrados via API e aí, posteriormente, o João consegue transferir esse dinheiro para a conta bancária dele. E aí, aqui fica a dúvida, né? Se são esses gateways que vão estar fazendo essa gestão de cobrança e pagamentos, como é que o nosso app vai ter essa informação? Porque, pensa comigo, o cliente fez o primeiro pagamento, entrou no nosso aplicativo, pagou, a gente teve a resposta da API lá, pago, tudo certo, a gente liberou o acesso desse app. para o nosso usuário. Porém, passou um mês aí, esse usuário não pagou. Quem fez essa gestão, quem fez a cobrança e não recebeu a informação de pago ou não pago foi o gateway de pagamento. Como que essa informação que o gateway buscou do usuário, usuário pagou ou não, como que essa informação vai sair dali? e vai vir agora para o nosso aplicativo. Aí fica a dúvida, como é que a gente vai fazer essa gestão? E para fazer essa gestão, a gente utiliza os webhooks. Então, pessoal, webhooks nada mais são do que uma resposta automática de um sistema para o outro. Fazendo a comparação entre o webhooks e as nossas chamadas de API, Para fazer uma chamada de API, a gente faz uma requisição e a gente retorna, essa chamada de API retorna uma informação para a gente. Os webhooks já não, a gente não precisa fazer essa requisição. Alguma coisa acontece nesse nosso segundo sistema que ele gospe uma informação para a gente aqui, para esse nosso primeiro sistema. E aí trazendo isso para a nossa realidade aqui de gateway de pagamento, a gente tem aqui a loja do sistema do João e os gateways de pagamento. Quando um cliente passa um cartão para fazer a assinatura desse aplicativo, ele passa o cartão e a gente faz uma chamada de API. ir lá para o nosso gateway e o gateway responde com a informação se o cartão foi válido, se a compra foi aceita ou não. Compra aceita, criada a assinatura lá no gateway de pagamento, deu um mês ou um ano, dependendo como é que for, essa assinatura foi criada e configurada, deu esse um mês, a gente vai cobrar novamente desse cliente. Feita essa cobrança, o sistema do gateway de pagamento vai responder essa informação aqui para o nosso sistema para manter os dois sistemas corretos. Então, o cliente pagou nesse um mês ou não pagou, a gente vai manter ou tirar o acesso do cliente aqui no nosso software. E assim fecha todo o cenário do João. Ele tem o SaaS dele, conecta com os gateways. ele consegue fazer a transferência conforme os clientes forem pagando para ele e as assinaturas vão sendo atualizadas através do uso de webhooks conectando o Gateway com o seu aplicativo, mantendo tudo em sincronia. Então, pessoal, é isso que eu queria passar para vocês sobre assinaturas, sobre pagamentos, dar essa fundamentação inicial. Coisas bem iniciais, teóricas, mas muito importantes para a gente entender como as coisas funcionam por debaixo dos panos.
