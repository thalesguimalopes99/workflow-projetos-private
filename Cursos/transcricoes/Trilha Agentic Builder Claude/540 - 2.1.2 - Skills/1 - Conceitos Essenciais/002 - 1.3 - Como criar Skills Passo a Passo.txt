E agora vamos entender como você consegue criar uma skill do zero, qual seria o passo a passo. Beleza, vamos lá. O passo 1 é a gente se preparar. Basicamente uma skill... É uma automação. A gente vai pedir algo para o Cloud e aquilo vai vir de uma forma automática para a gente ter um output. Então a gente entra com o input e sai um output. Então você tem que conhecer o processo. Para isso você tem que se organizar. Primeiramente, você tem que estruturar qual é o mapeamento do processo. Se a gente pega o exemplo do LinkedIn, que estava criando os posts para mim por meio de um link do YouTube, tinha toda a parte que eu tinha que assistir o vídeo, depois eu tinha que estruturar qual seria o começo das linhas ali, as primeiras linhas. do texto do LinkedIn, e depois eu teria que fazer todo um checklist para ver se eu estou seguindo boas práticas para criar esse texto, e por fim, eu também geraria a imagem que demoraria muitas horas se eu fosse fazer sozinho, sem A. Então, aqui primeiro você vai fazer o mapeamento do processo. Então, vai descrever o início ao fim, como funciona o processo hoje sem o Cloud. Primeiro faz o fluxo atual. da sua automação que você quer fazer. Deixa claro para o Cloud também qual é o gatilho. O que faz essa skill ativada? Se é uma mensagem, é um arquivo que você enviar, é um evento, um comando, ele precisa entender quando ele vai ativar aquela skill. Beleza? Então no caso do meu do YouTube, era toda vez que eu pedia, cria um post do LinkedIn Viral a partir desse link do YouTube. Além disso, tem documentos e arquivos usados. Então você tem que listar todos os materiais que você está usando, exemplos, dados, contexto. Então deixar bem claro aqui que vai ser importante para o Cloud entender. Aqui também vamos ter ferramentas. Então quais MCPs, APIs, integrações que vai precisar acessar. Então tem alguma conexão com outra aplicação que precisa para criar o seu projeto. E por fim, um exemplo da entrega final. Mostre de um a três exemplos reais como o output deve ser. Isso é o critério de sucesso. Então o Cloud tem que entender qual é o output esperado. No caso da minha automação, eu tinha lá as minhas imagens que eu deixei como referência que eu queria. Então ele sempre vai seguir aquelas imagens. Então isso daqui é a preparação. Vamos ver mais um exemplo em relação à preparação. Vamos supor que eu estou fazendo uma skill de dashboard. Toda vez que eu enviar dados de um relatório mensal, por exemplo, eu quero que meu cloud crie um dashboard, só que eu quero que ele crie com minha identidade visual, seguindo a minha estrutura, mantendo a consistência e de forma automatizada. Mas o que a gente vai fazer depois? Primeiro você mapeia o processo. Então, toda semana recebo dados de vendas e monto um dash manualmente. Hoje, baixa a planilha, abre Excel, copia as métricas, cola um template, echa os cores, salva, leva duas horas. A Skill vai replicar isso automaticamente no padrão visual toda vez. Então, qual é o processo que você já faz manual e você quer automatizar? Além disso, tem um gatilho. Então, envia um arquivo CSV para o Cloud. Toda vez que eu enviar esse arquivo, eu vou pedir, gero o dashboard de vendas. Nada mais. A Skill vai entender que vai ter que ser ativada e vai começar. Beleza, já entendeu o processo e entendeu o gatilho. Também tem os documentos. Quais são os documentos principais? Tem CSV de vendas, mais identidade visual, que eu quero que sempre gere nas cores da minha empresa. E um exemplo de dashboard também seria interessante. Então a SQL precisa ter acesso à estrutura das colunas de CSV, produto, data, paleta de cores, fonte de marca, um dashboard anterior como referente de layout. Então quanto mais arquivos você der, mais ele vai seguir aqueles templates. Show! Em relação às ferramentas... tem que entender qual que é a integração, né? Se tem alguma integração, ou não tem uma API, precisa acessar outra plataforma. No caso lá do meu LinkedIn Posts, ele acessa a API do Nano Banana. Então eu tenho que passar como é que vai funcionar essa integração e a chave API, tá? No caso aqui, não tem MCP, não tem IP, não tem API, ele vai ler automaticamente, tá? Mas a gente poderia colocar aí alguma automação, por exemplo, para enviar um e-mail ou para fazer algo parecido. A entrega final, então, dashboard HTML com gráfico, KPIs, identidade visual da Max. Tem que deixar claro o que você quer no final. Então, no caso aqui, eu vou mandar dados de uma planilha. E a partir dessa planilha, eu quero que saia no dashboard bonitão, lá com uma identidade visual e sempre igual o modelo. Mas isso vai variar os dados. Toda vez que eu enviar esse CSV, eu quero que ele gere esses dados. Beleza, então você já fez a preparação, já entendeu o processo. ferramentas, todas as conexões, que é a parte que mais dá trabalho, tá? Depois você vai criar o prompt lá com o chat, tá? Então, coleta tudo que você mapeou na etapa 1, o processo, o gatilho, os arquivos, as ferramentas, a entrega, e pede ali pro chat lá da Cloud, ou o cowork, ou o chat normal mesmo, só pra ele criar um prompt, seguindo boas práticas. Então, peça ao Cloud Chat pra organizar isso no prompt estruturado. Então... pede para ele que quer criar uma skill, aí ele já vai dar o contexto, vai dar o gatilho, o processo, a identidade visual, ele basicamente vai organizar para quando você for começar a criar skill, já vai vir tudo bem desenhado, tá? Então dessa forma aqui fica bem legal e dá um resultado muito massa. Basicamente é para você não sair tudo desorganizado. E daí a gente vai para a criação, tá? Então a gente vai lá no Cloud Coork, se for uma skill mais individual, uma automação mais independente, se for uma skill mais estruturada, algo relacionado com o desenvolvimento, a gente vai no Cloud Code, tá? A gente vai abrir o novo projeto, vai colocar os itens, vai ativar o modo plano, tá? Toda vez que a gente for começar, a gente ativa o modo plan, para ele ajudar a gente a planejar antes de executar a skill. Então a gente passa pelo modo plano. passando aqui nosso prompt que a gente copia lá e cola aqui, tá? E crie em conjunto. Pede pra ele perguntar se ele tiver alguma dúvida, que ele vai perguntando, vai ajustando e daí a gente vai melhorando e testando, tá? E no final a gente vai salvar a nossa skill e ele vai estar lá no nosso app para ficar mais fácil integrar. Então basicamente você vai ter uma pastinha no seu computador. A gente vai pedir para o Cloud criar essa skill. Então ele vai criando essa skill em conjunto, te perguntando algumas coisas. A gente vai testando e se tiver algo que você não gostou, você pede para ele arrumar. E dessa forma a gente vai atualizando. Então basicamente aqui no texto segredo... Todo o trabalho é lá com o Cloud. Mas um ponto super importante é a melhoria contínua da sua skill. Então a gente tem todo o passo aqui, que eu repliquei para o ciclo PDCA, que é o ciclo de planejar, executar, medir e agir. É um ciclo contínuo. A gente também tem ciclo contínuo para a melhoria das skills. A gente planeja as skills, a gente cria as skills, testa e interage aqui. A gente age. Aqui é muito importante porque vai ter coisas que não vão ficar tão boas do jeito que você quer. Então o segredo vai ser você sempre interagir para cada vez a sua skill ficar mais afiada e mais com a sua cara. Por exemplo, a minha skill do LinkedIn, eu poderia melhorar aquelas imagens, colocar um pouco mais na minha unidade visual, colocar um pouco mais de desenhos, colocar mais cores. Então a gente vai melhorando até ter resultados melhores. Então isso que vai... fazer a sua skill realmente ser uma skill profissional e que vai dar resultado. Então é um ciclo de melhoria contínua. Resumindo, você vai planejar, estruturar o Pronto, criar em conjunto com o Cloud e melhoria contínua. É só seguir os passos que a gente vai ver na prática nos próximos cases, mas é importante para você que quer automatizar alguma tarefa.
