Turma, agora vamos falar sobre versionamento e a importância de você ter versões para o seu projeto. Como é que funciona isso? Para falar sobre a importância sobre versões, o que seria o versionamento? Basicamente é a foto... toda a linha do tempo do seu projeto para a gente conseguir ter o controle total das mudanças e das melhorias que a gente vem fazendo. Quando a gente não tem um relacionamento, por exemplo, você tem um relatório final lá que você está criando. Aí você cria o relatório final, aí depois você entra no final 2, aí o V3, aí coloca o final de vez, esse mesmo. Aí a gente não sabe qual que é o certo, o que mudou, vira uma bagunça. Com o relacionamento é sempre o mesmo arquivo, só que a gente vai ter um histórico de fotos das mudanças desse arquivo. Isso daqui é bem importante. fazer essa parte de a gente controlar as versões, vão ser duas ferramentas o git e o github o git vai ser toda a parte do versionamento que a gente vai fazer na nossa máquina no nosso computador, então a gente vai controlar a versão do nosso projeto pelo nosso computador. E o GitHub vai ser a parte do versionamento que a gente vai jogar para a nuvem. Então a gente vai jogar e deixar salvo lá na internet as versões do nosso app, tá? Isso vai facilitar a gente criar projetos mais robustos, vai ajudar a gente trabalhar em equipe com os projetos. Então sem o versionamento, em empresas a gente não consegue criar esse tipo de projeto em conjunto, tá? No Git, vai ser a ferramenta local, rastreia as mudanças do seu projeto, funciona offline, cria e gerencia branches, que nada mais é que linhas de mudanças que a gente vai fazendo, salva esses snapshots, tem essas linhas de comando, então o Git é a interface, é a parte técnica que a gente vai usar para salvar essas versões. E a gente tem o GitHub. O GitHub é uma plataforma online. A gente salva essas versões. E no GitHub lá, a gente vai deixar salvo as versões e esses snapshots. Então vai ficar em nuvem. A gente consegue colaborar com times, com pessoas. A gente vai mandar um pull request. Que é quando você quer que mande a atualização. É um PR que a gente fala. Um PR. A gente está mandando um pull request para conseguir atualizar. A gente consegue rastrear aqui problemas e melhorias, bugs, fazer automações. Então muita coisa. Basicamente aqui, o Git vai ser um diário pessoal onde você anota tudo que o seu projeto mudou. E o GitHub é uma biblioteca pública, onde te deixa aberto para quem é esse diário compartilhado com outras pessoas. Então lembra que a gente tem o Git e o GitHub. E daqui vai ser bem importante. Vou fazer um exemplo aqui, como os dois trabalham juntos. Primeiro, você edita aqui o seu projeto localmente, você trabalha na sua máquina, no seu computador, faz um commit. Um commit nada mais é que é grupar. Em várias mudanças, melhorias e salvar aquelas mudanças, tá? E aí você salva isso nessa linha do tempo, tá? Aqui tem alguns códigozinhos, mas fica tranquilo, você precisa saber só o básico, depois Cloud Code e outras ferramentas de A, elas vão fazer para você, tá? Depois disso vem o GitHub. A gente consegue enviar para a nuvem. Então a gente envia o histórico para a nuvem. A gente faz um Git Push, que é empurrar para a nuvem. E depois a outra pessoa vai baixar as mudanças se você estiver trabalhando em equipe. Ou você mesmo consegue fazer um Git Pool para puxar a versão mais atualizada do projeto. E aí o time consegue trabalhar em paralelo. Então basicamente a gente consegue ter várias pessoas trabalhando em paralelo lá com o Git. Depois elas vão subindo para a nuvem. Vamos dar alguns exemplos aqui. O que seria uma branch? Uma branch é uma ramificação de uma cópia do projeto. Você experimenta, quebra, conserta, sem tocar na versão que está funcionando. Quando terminar, unir de volta, que é o merge. Então, se a gente tem aqui o nosso projeto, a gente cria uma branch, a gente basicamente clona o nosso projeto para a nossa máquina, a gente vai fazer melhorias e deixar a nossa feature pronta. E para voltar aqui, a gente tem que dar um merge, que é unir o que a gente fez lá na nossa branch paralela aqui na branch principal. Então, basicamente, a gente desenvolve uma nova funcionalidade e salva essa funcionalidade na nuvem. Dessa forma, a gente tem o snapshot de várias... fases do projeto aqui ó por exemplo a correção de um bug, a gente tem uma branch principal, a gente vê que a gente precisa corrigir um bug, a gente clona o nosso projeto começa a corrigir ele, faz a correção e volta aqui pra produção Então a gente vai lá e faz essa correção. Se você quiser se trabalhar aqui com times compartilhados, né? Então cada um vai puxar esse projeto, vai fazer a sua funcionalidade, né? A Ana aqui tá trabalhando, o Bruno tá trabalhando, o Carol tá funcionando. E aí vão colocando de volta aqui nas branches principais, tá? Três pessoas trabalhando ao mesmo tempo, em parte, finindo o projeto sem nenhuma interferência. Cada merge acontece quando cada tarefa está pronta, tá? Então aqui é realmente o básico do básico para você entender a importância do versionamento, quais são as ferramentas envolvidas. Depois a gente vai entender na prática. Você vai ver que é tranquilo. Todas as partes chatinhas a gente vai ter se eles aprear. Então pode ficar tranquilo que vai ser mais fácil de ter o controle e versionamento do nosso projeto. Beleza? Entendido?
