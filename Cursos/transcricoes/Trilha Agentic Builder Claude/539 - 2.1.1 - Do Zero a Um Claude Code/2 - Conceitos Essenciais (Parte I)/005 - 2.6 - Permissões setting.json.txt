E bora falar sobre um arquivo importante da nossa pasta, que é o setting.json. O que é esse setting.json? Basicamente vai ser o nosso painel de controle. É onde a gente vai definir as regras de comportamento do projeto do cloud. O que ele pode fazer, o que ele está bloqueado, quais são as variáveis de ambiente, quais são os hooks e muito mais. Sem ele, o cloud roda com as configurações padrões, sem restrições personalizadas. Então o kit consegue... Tem um parâmetro de controle sobre a segurança e as permissões. E onde ficam os arquivos? A gente tem alguns tipos de arquivos. A gente tem o global, que basicamente vai ficar na nossa pasta global. Lá na pasta global, lembra que tem o tio aqui. Cloud7GISM1 vale para todos os projetos. Suas preferências pessoais, ferramentas que você usa, configurações que você quer em qualquer projeto. Então a gente vai colocar aqui, se te mexer nesse set de pontos de som, ele vai estar... mexendo em todos os projetos. A gente pode focar também só em um projeto. Então a gente pode falar assim, essas configurações vão valer só para esse projeto. Então ele pode ser comitado, que a gente salvar na nuvem, e compartilhado com o time. A gente pode colocar as permissões e os hooks específicos desse projeto. Ou também tem a pasta local. A gente tem um settings.local.json que é só para você ir dentro desse projeto. Então aqui você não vai colocar no Git, é apenas ajustes para esse projeto e que valem para você. Então essa daqui é a estrutura e os locais que a gente consegue atualizar em relação ao setting.json. E o que a gente vai configurar lá dentro desse arquivo? Primeiramente, as permissões, então o que o Cloud pode fazer, o que o Cloud não pode fazer. Então uma lista de allow que a gente libera a confirmação. Deny, que é bloquear para sempre. Por exemplo, a gente pode permitir algumas ações específicas. Isso daqui tem algumas configurações importantes para a gente fazer também a nível de segurança. Os hooks, que basicamente são os gatilhos automáticos. Então, eu vou definir aqui o que acontece automaticamente dentro do cloud. Exemplo, formatar um código, pós-edição, notificar quando terminar. Então, a gente vai deixar os hooks aqui dentro do setting.json. A gente também tem a env, que são as nossas variáveis de ambiente. As variáveis que se aplicam em todas as auto-accessões automaticamente, a chave de API, configurações, então a gente vai configurar lá dentro sobre se o Cloud pode acessar ou não. E também temos a parte do sandbox, que é a proteção em nível de sistema. Basicamente é um módulo do Cloud Code que vai ter uma restrição a nível de sistema operacional, a gente vai bloquear o acesso dos arquivos, mesmo que o programa do Cloud execute. Então isso daqui é bem importante e depois a gente tem algumas configurações aí de segurança para deixar isso estruturado. Mas aqui só foi o conceito principal para depois você já ir entendendo os arquivos quando a gente vê no projeto, o que funciona para qual tipo de objetivo cada arquivo. Então na hora que a gente for mexer ali no nosso JSON, na nossa parte aí do nosso arquivo 7JSON, a gente consegue já deixar organizado, fica mais fácil para a gente entender, beleza? A gente vai fazer isso mais para frente. Bora lá!
