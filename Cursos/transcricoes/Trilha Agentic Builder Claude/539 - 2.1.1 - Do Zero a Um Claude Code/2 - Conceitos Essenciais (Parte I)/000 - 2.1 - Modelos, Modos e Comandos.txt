Agora bora entender os modelos, as formas de trabalho, que são os modos e também os principais comandos. Beleza, em relação aos modelos do Cloud, a gente tem três principais modelos atualmente. Tem o Raiko, tem o Sonnet e o Ops, cada um com um objetivo. O Raiko é o rápido, o velocista, basicamente ele vai dar respostas muito rápidas, o raciocínio mais básico. mas o custo de token também é mais básico. Então perguntas rápidas, pontuais, tarefas repetivas. Se a tarefa é clara e simples, você precisa da resposta imediata, pode usar aqui o Raico. O SONET é para quando a gente está usando no dia a dia. Geralmente a gente vai usar bastante esse, que a gente consegue ter uma velocidade também de resposta rápida, um raciocínio bom, um custo de tokens médio. Então é mais focado para o desenvolvimento no dia a dia. Escrita, código de lógica, code review. Na dúvida aqui, a gente vai usar o SONET. E o terceiro modelo é o Opus, que a gente consegue ser a parte mais especialista em projetos mais complexos. Então, arquitetura, edições complexas, revisão final, bugs difíceis, reorquestração. A gente geralmente vai usar quando uma tarefa é crítica, mais complexa, a gente vai usar o Opus, só que ele é mais caro, então cuidado. Um fluxo aqui recomendado é começar pelo Opus, que a gente consegue planejar o nosso projeto inteiro de uma forma bem detalhada. O Raico aqui para fazer telas rápidas, o Sonic Logicas, o Sonic. Logicas, APIs e integrações E o Ops para revisão final De forma geral a gente vai entendendo como vai ser a prática No dia a dia, a gente vai usar bastante o Sonnet E o Ops aqui só para algumas tarefas específicas Legal A gente também tem os modos de trabalho aqui no Cloud. O modo 1 é o Plane Mode. Basicamente, a gente vai fazer planos com o Plane Mode. Então, o Cloud vai só ler e não vai editar nada. Vai apresentar um plano completo aqui para a gente aprovar. Daí, a gente vai revisar e autorizar. Quando uma tarefa é grande, um projeto grande, um projeto completo, a gente vai usar o Plane Mode. A gente também vai ter um modo normal, onde o Cloud vai pedir a permissão e editar a cada passo. Então, ele vai pedir a permissão. quando a gente quer o equilíbrio do dia a dia para o modo padrão. Então, geralmente, para o Grid Project a gente faz o Play Mode e depois a gente vai lá para a execução. E também temos o modo Auto Accept. Basicamente, o Cloud vai editar os arquivos sem pedir permissão. Ele vai executar de forma autônoma e ainda pede ok para algum comando terminal. Tarefa clara, simples, a gente vai ver isso aí no dia a dia. Um fluxo recomendado pelo criador aqui do Cloud Code. A gente começa no Play Mode para projetos novos ou tarefas completas. Discuta o plano e ajusta até estar bom. Depois mude para AutoSept e deixa o Cloud executar.
