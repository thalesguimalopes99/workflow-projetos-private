Bora falar sobre um tema importante no Cloud Code que são os Agents e os Sub-Agents. Pra você entender, a gente já falou muito sobre o Cloud Code aqui, mas a tecnologia por trás aqui do Cloud Code é um super agente, né? Se a gente pudesse chamar assim. A diferença é que esse agente lá do Cloud Code, ele vai conseguir agir e vai conseguir interagir com várias ferramentas aí do mundo real de uma forma autônoma. Então quando a gente pede algo aqui... para o Cloud Code, ele vai entrar em um loop agêntico, basicamente é esse daqui, que é todo o ouro do Cloud Code. Ele primeiro vai coletar o contexto, ele vai ler arquivos, vai buscar código, vai entender o que você falou, ver documentos que você falou que tinha algo aqui para ele entender exatamente o contexto. Daí ele vai conseguir agir por conta própria, então ele vai conseguir editar, executar, fazer pesquisas, ele consegue ir atrás de outros documentos. Ele consegue verificar também para testar e comparar para ver se aquela informação que ele fez está correta e daí ele pode vir e voltar. Ele fica nesse looping aqui até conseguir entregar um bom output. E tem dois componentes aqui muito importantes que fazem o diferencial. Primeiro é o modelo que você coloca, qualquer LLM que a gente coloca. Se a gente vai usar o Sonnet ou se a gente vai usar o Opus. O Sonnet vai ser o modelo mais simples e o Opus vai ser o modelo mais robusto. Mas aí vai gastar um pouco mais. Então o modelo aqui vai fazer muita diferença nesse ciclo. E além disso tem as ferramentas. Ferramentas ou tools, basicamente, vai conseguir se conectar com outros sistemas, vai conseguir, por exemplo, editar arquivos, atualizar, escrever novos dados em um banco de dados, por exemplo. Então ele consegue realmente ter ação, não só realmente criar texto, ele vai realmente em outras ferramentas e criar novos dados. Então, junto com o modelo e junto com as tools, tudo isso aqui forma um looping agêntico que faz o Cloud Code, no final, intergar aquela sua tarefa, sendo que você pode interromper a qualquer momento. Então essa daqui é a grande inteligência do Cloud Code. Basicamente ele é um agente que vai fazer um milhão de coisas para a gente, porque ele tem um modelo diferenciado e tem as ferramentas integradas. Dito isso a gente consegue entender sobre sub-agents. Para que serve sub-agents, os sub-agentes? Basicamente a gente vai ter o agente principal aqui do Cloud Code, que é o que a gente falou agora. Então ele vai resucionar, vai decidir, vai delegar tarefas e daí ele pode ativar... alguns sub-agentes, que são agentes que já tem nativos no Code Code, ou você mesmo pode criar para uma tarefa específica, para algo específico. Então, por exemplo, tem aqui o Explorer. Ele usa o modelo Raico, então ele vai ter o contexto próprio. Aqui vão ser agentes que ele vai ativar... Primeiro, para conseguir ter um contexto limpo, então ele vai conseguir ter um contexto limpo aqui para conseguir trabalhar dentro de uma tarefa específica. E daí esses subagents conseguem entregar um resultado final, um resumo, para o agente principal sintetizar e entregar a resposta para você. Um subagent é uma instância separada do Cloud Code, com contexto próprio, isolado, que executa uma tarefa e desenvolve apenas o resumo. Então, em resumo, os benefícios é que a gente vai ter esse contexto isolado e limpo. Quando a gente está conversando muito tempo com o Cloud Code, vai aumentando o contexto dele. Isso não é muito bom para conseguir entregar resultados de boa qualidade. Por isso que ele ativa um agente. Quando a gente ativa um agente separado, um sub-agent, ele vai ter o contexto basicamente zerado, limpo. Então, isso daqui vai deixar muito mais efetivo as nossas entregas. Além disso, tem o paralelismo. Então, quanto você está fazendo uma tarefa, outros sub-agentes estão fazendo outras tarefas. Então, a gente consegue entregar de forma mais rápida. A gente consegue ter uma especialização, a gente consegue criar um agente específico, especializado para uma determinada tarefa, um determinado processo e... também consegue ter um controle de custos, às vezes tem uma tarefa específica que a gente precisa ativar o Opus, mas na outra pode ser um modelo mais simples, pode ser um High Core, então a gente consegue trabalhar com esses modelos para economizar. Então esses daqui são só alguns dos benefícios da gente ter sub-agents. E como eu falei, o Cloud tem alguns sub-agents nativos que já vem preparado aí na sua estrutura. Tem o Explore, o Plan, o General Purpose e o Cloud Code Guide. Basicamente o explorador aqui, ele vai usar o modelo mais barato, o Raico. Ele vai ter uma ferramenta só de leitura, então ele não vai fazer nenhuma edição, nenhuma corte de dados. Ele vai entender o código antes de agir e vai buscar fora do contexto principal um resumo. Então basicamente ele vai entender o contexto do código. O plano aqui, ele vai realmente fazer um plano, ele vai usar o modelo que você está usando na sua sessão, e ele basicamente ativa o plan mode, então ele vai ativar o modo plano para conseguir pesquisar e fazer planos sem modificar nada. Tem o general proposal aqui também, que é parecido, ele vai ser mais para tarefas complexas, que precisa explorar e modificar ao mesmo tempo, aqui já vai ter ferramentas todas, então ele vai conseguir editar, e tem o Cloud Code Guide, basicamente, quando você quer ativar algo da documentação do Cloud Code, ele vai lá, Vai buscar essa informação e vai trazer de volta sempre com o contexto líquido. Aqui é importante você entender a inteligência por trás do Cloud Code, que é um agente e para que serve o Sub-Agents. Então a gente tem os agentes nativos do Cloud Code e a gente também consegue criar os nossos próprios agentes para fazer tarefas específicas. A gente vai criar aí depois ao longo dos processos e nossos projetos. Na próxima aula vamos ver como a gente faz isso na prática.
