E agora que a gente já criou um projeto na prática, vamos entender como seria o processo padrão para criar novos projetos de tecnologia lá no Cloud Code. A gente tem um processo mapeado por aqui, que dá bem certo de acordo com a qualidade dos nossos projetos. Bom, primeiro, a fase 1 é de preparação, fase 2 de planejamento e a fase 3 de execução. Tem algumas fases que é importante você colocar o seu insumo, realmente a gente parar, pensar, escrever, pensar no que a gente vai pedir para o cloud. Outras a gente só vai deixar o cloud fazer porque realmente ele é muito bom no que ele está fazendo ali na entrega de projetos. Na fase 1, a primeira coisa que a gente vai ter que fazer vai ser criar o PRD. Então a gente já teve uma aula sobre isso, vou deixar o link aqui embaixo. Basicamente você tem que falar o que você quer construir, qual o dobro que você está resolvendo, qual que é a solução, quais são as features, tecnologias que você tem interesse em fazer. Em relação aos usuários também, coloca referência de design. Então quanto mais focado você pedir para o Cloud Code o que você quer, melhor ele vai te entregar, tá bom? Se você pede algum genérico, ele vai te entregar algo bastante genérico. Então, o PRD, basicamente, é um documento para a gente falar o que a gente quer. E aí, com ele, a gente vai gerar aqui o nosso Cloud MD, né? Então, você pode criar tanto do zero o Cloud MD, que é a instrução, ou você pode criar com ele, tá? e também depois a gente vai criar com ele a parte de todo o desenvolvimento ali dos arquivos env, gitignore para fazer o primeiro commit. O primeiro commit basicamente a gente fazer a integração entre o git e o github e conseguir dar o start naquela foto. Depois dos próximos modos a gente fazer plan, a gente fazer projetos aí passo a passo você vai entender como que a gente faz o salvamento do projeto e como a gente manda lá para o github, tá? Mas aqui você já vai entendendo. E daí a gente gera junto com o Cloud Code o planejamento. Então a gente vai gerar aquele arquivo de plano. Vamos pedir para ele colocar no plano com mais tones ou com fases. Vamos revisar esse plano para ver se está tudo certo. Pedir para ele alterar algo do plano se a gente não concordar. E também a gente vai dar um commit no plano. Um commit nada mais é que a gente salvar a nossa linha principal do projeto. Depois a gente vai entrar em um looping de execução. Como a gente vai ter fases ou mais tones de desenvolvimento, a gente sempre vai começar. Resetando o contexto, vamos criar a nossa branch, que é a nossa linha principal do projeto. Vamos fazer a execução junto com a Cloud Code, fazer um teste, pedir para ele revisar tudo o que fez, dar uma olhada a gente mesmo, o teste humano, testar algumas coisas no nosso projeto, ver se está funcionando, e daí a gente junta de novo na branch principal. Então lembra que a gente tem a nossa branch geral, a nossa linha geral do projeto. clona ela, basicamente a gente pega uma cópia do projeto, faz as nossas modificações e volta. Então a cada fase, a cada milestone, a gente vai repetir esse processo. Então, para a fase 1, nosso projeto, para o milestone 1, ele vai lá, vai desenvolver, a gente vai lá e salva. lá no GitHub, na nuvem. Fase 2, vamos lá, vai desenvolver e salva de novo. Então a gente vai fazendo isso, dessa forma a gente garante qualidade e controle aí de qualidade do nosso projeto, tá? Isso daqui é um processo geral, ao longo das aulas a gente vai fazendo isso com calma, geralmente o Cloud vai fazer toda a parte chata pra gente, a gente só precisa entender alguns pontos de como gerenciar o agente de A do Cloud, tá? Mas vamos ver bastante nas próximas aulas, só pra te deixar claro qual que é esse processo de desenvolvimento. Dito isso, Bora que estamos quase finalizando esse primeiro módulo de Cloud Code. Bora lá.
