Bom pessoal, então bora entender como testar o teu aplicativo em diferentes plataformas. Para isso, eu separei essa seção de perguntas e respostas aqui. A primeira delas é como testar um app web. Bom, o próprio modo Run e modo teste do Flutter Flow já indica o modo web para você testar, ok? Sempre que você abre um desses módulos, você está testando, na verdade, o teu app na web. Por mais que apareça uma janelinha de um telefone ou de um tablet, Muita gente às vezes confunde achando que está testando o app de forma nativa, mas não, aquilo lá é só o formato web, ok? Então, para deixar bem claro, modo teste e modo run já são o modo app do teu aplicativo. E se é o modo teste, aliás, se é o modo web, você tem acesso aos recursos do navegador, para fazer o debug, para analisar as chamadas API, tudo que o navegador oferece naquela opção ferramentas do desenvolvedor, você consegue usar para debugar o teu aplicativo. Beleza? Na sequência, como testar um app Android? Você pode baixar o seu código no Flutter Flow e testar no emulador, que é exatamente o objetivo dessa aula. Ou você pode baixar o APK e instalar no teu dispositivo Android. O APK nada mais é que um arquivinho de instalação. Na hora que você clica nele, ele já reconhece que é um arquivo de instalação. E você consegue, obviamente, instalar o teu app para usar. É bem simples. É muito mais simples que no iOS. Ok? E por último, como testar o app iOS? Você vai precisar de um Mac. um computador da Apple, para rodar a sua aplicação no emulador dentro do Xcode, que é a IDE oficial da Apple. A IDE é basicamente o editor de software e nela você pode rodar um emulador para testar o seu aplicativo. Só que, além dessas três opções, o Flutter Flow lançou recentemente o Local Run, que é essa fotinha que vocês estão vendo do lado. O que o Local Run faz? Lembre que o Flutter Flow roda no seu navegador, certo? Porém, você consegue baixar o Flutter Flow nas versões desktop também, tanto para MacOS quanto para Windows. E nessas versões baixadas, você consegue usar essa opção do Local Run, que nela você pode basicamente testar a tua aplicação num emulador ou num dispositivo físico, ou ambos em paralelo, como é o caso da foto aqui, onde o cara está testando um aplicativo tanto no MacOS dele, quanto no iPhone, em paralelo. Então, qual é a vantagem disso? Lembra que na hora que você vai testar no modo TESH ou RUN, você tem um limite de sessão. Aqui no local RUN, o seu tempo é ilimitado. Você pode testar à vontade, além de outras vantagens. Mas isso facilita muito na hora de debugar o teu aplicativo também. Você consegue testar as funções nativas dele. Lembre que agora você está testando ele de forma nativa no local RUN, e não na web como é no modo TESH ou modo RUN. E só uma observação. O local run para macOS aparentemente está rodando ok. Não vi muita reclamação em relação a isso. Porém, na versão do Windows, eu vi que ainda tem uns problemas. Tanto na comunidade, o pessoal está destacando que começou a travar no começo. Eu mesmo não consegui testar. Na hora que abre, ele dá um probleminha de atualização. Fecha automaticamente. Então, tem vários probleminhos ainda que eu tenho certeza que a equipe do Flutter Flow vai corrigir, mas até o momento ainda está um pouco travado. Então, é por isso que eu nem vou mostrar ele aqui. Mais para frente, quando tiver uma versão mais estável, a gente vai fazer um módulo específico falando sobre o Local Run para Windows e o Local Run para MacOS.
