Pessoal, na última aula eu expliquei a importância de gravar o banco já em UTC. Mas como é que a gente faz isso na prática? Basicamente, eu criei uma função chamada DayTimeToTC. Essa função recebe um argumento de entrada, que é um único UTC, não é uma lista, é só um único UTC. E ela retorna um DateTime, também um único DateTime, não é uma lista. Esse cara aqui utiliza a função ToTC e é retornado para o usuário. É só uma única linha de código. para transformar a data que o usuário selecionou, a data e horário, no formato TC para ser gravado no banco. E onde que essa função é utilizada? Bom, aqui no modo de agendamento, lembrando que esse aqui eu tenho dois, o que eu já tinha feito e o que eu fiz com vocês do zero. Eu vou usar o que eu já tinha feito para agilizar. Basicamente, no botão de agendar, na hora que eu clico, ele insere uma linha. Essa linha lá no banco, na tabela agendamentos, inserem uma coluna chamada horário, um campo chamado horário. Esse horário aqui não é o horário que a pessoa selecionou, e sim o retorno da função, já convertido em UTC. Então, repare que ele chama a custom function e passa como argumento para ela um date time. Esse date time é exatamente a data e hora selecionada. E de onde vem essa informação? Aqui, na hora que eu clico no horário, repare que tem uma ação no container. Na hora que eu clico aqui, Ele vai lá e atualiza uma variável local de componente, que é uma component state. Aqui, local component state variable. Eu criei uma variável chamada data e hora selecionada, do tipo date time, que não é uma lista, é uma única data. Toda vez que eu seleciono um horário aqui, ele alimenta essa variável, que é exatamente o que a ação está fazendo. Se eu clicar aqui, ele está fazendo um update component state, setando o valor. para o item atual do meu Dynamic Children. A única diferença é que nesse Dynamic Children eu chamei de Timeslots. Se eu revisar aqui com vocês, o nome desse Dynamic Children é Timeslots, diferente do anterior que a gente tinha chamado de Datas Dynamics. É só isso que mudou, ok? Aqui no card de agendamentos, eu chamei o Dynamic Children de Timeslots e estou utilizando o item atual na hora de clicar. Ou seja, se eu clicar nesse cara aqui, Ele vai atualizar a variável de componente que eu acabei de mostrar, colocando a informação do item atual. Como assim item atual? Repare que como ele vai gerar de forma dinâmica, ele vai gerar vários containers aqui. Então, o atual é o que vai ser inserido nessa variável de componente. Como é que a gente sabe que é o atual? Porque eu estou utilizando o time slot item no singular, ou seja, o item da vez, o item que está sendo selecionado. Bom, é assim que a gente consegue salvar o horário que o usuário selecionou em uma variável local e utilizar essa variável local para alimentar a função que converte o UTC. Então, essa função aqui, o UTC, está recebendo como argumento a data e hora selecionada que vem da minha ComponentState. É assim que a gente faz com que o usuário selecione uma data e eu converta. para o TC e porque a gente converte para o TC lembra que se eu quando eu salvo uma data e horário lá nos para base ele já entende que aquilo está em o TC então na hora que eu tento recuperar essa informação o banco aliás o meu navegador ele converte para o TC menos três que é o horário do Brasil então se eu gravar 11 horas da manhã ele vai trazer oito horas para mim isso não é interessante porque eu tô trabalhando com agendamentos eu preciso ter exatamente a data que eu passei Então, para fazer isso, ou seja, para garantir que a data que eu passei é exatamente a que eu recebo, eu preciso converter em UTC antes de mandar para o banco.
