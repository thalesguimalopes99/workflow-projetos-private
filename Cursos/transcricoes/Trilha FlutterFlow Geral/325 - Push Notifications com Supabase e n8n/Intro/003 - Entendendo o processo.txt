Pessoal, então bora entender como é que funciona todo esse processo. Aqui do lado direito da tela, eu tenho um resumo entre Firebase e Google Cloud. Toda vez que você cria um projeto no Firebase, você também está criando um projeto lá no Cloud, ok? No Google Cloud, eu tenho acesso a várias APIs para acessar diferentes serviços. Um desses serviços é o FCM, que é o Firebase Cloud Messaging, ok? E para usar o serviço do FCM, existem duas formas. ou baixando SDK ou fazendo requisições para a API do FCM, que é exatamente o exemplo que a gente vai usar nesse módulo. E para acessar essa API, existem alguns tipos de credenciais diferentes, sendo que nesse módulo especificamente a gente vai usar a conta de serviço, porque é o tipo de credencial do Google que permite que uma aplicação converse com os recursos do Google. Então, eu não poderia usar o ALF nem a chave de API, por exemplo, porque eu estou fazendo com que o N8N converse com o Google Cloud. Então, eu preciso de uma credencial específica para isso. Eu até tenho uma definição aqui. Contas de serviço são contas que não representam um usuário humano. Eles oferecem uma maneira de gerenciar a autenticação e autorização quando uma pessoa não está envolvida diretamente, como quando um aplicativo precisa acessar. os recursos do Google Cloud, ok? Isso é uma definição da própria documentação do Google, beleza? Bom, tendo em vista esse cenário do Firebase, do Cloud, de como acessar o FCM e quais são os tipos de credencial, agora a gente vai entender como que é o processo lá no Flutter Flow e no Spabase. Basicamente, eu preciso criar um projeto Firebase pelo Flutter Flow, mas isso não significa que você vai usar... que você necessariamente precise usar a autenticação do Firebase, ok? A gente vai usar a autenticação do Spapase. A gente só precisa criar o projeto de forma gratuita lá no Firebase, beleza? Uma vez que eu criei o projeto no Firebase, eu preciso criar uma custom action para solicitar um token do FCM para o dispositivo. Como assim? Basicamente, a gente vai solicitar lá para o FCM para que ele... registre o meu dispositivo, ou seja, ele forneça um token que represente o meu dispositivo, ou seja, toda vez que ele for mandar uma notificação, ele vai mandar para aquele token. Lembrando que a notificação é para o dispositivo, não é para o usuário. A gente vai ver uma forma de mandar para usuários específicos, mas só para que fique claro, a notificação é para o dispositivo, ok? Nesse momento, o FCM não tem ideia de quem são usuários da minha aplicação, beleza? E por último, a gente vai criar uma tabela lá no Superbase, associando esses tokens, lembra que esse token é um registro do meu dispositivo lá no FCM, a gente vai criar essa tabela e vai associar esses tokens a cada usuário. Aí sim, a gente vai conseguir segmentar as nossas mensagens, beleza? Na sequência, a gente vai fazer esse processo no Google Cloud e no N8N. Então, como é que funciona? Basicamente, o N8N solicita um token usando a credencial da conta de serviço, que eu expliquei no início desse vídeo. O Google Alpha avalia e retorna um token. Ele fala, ó, N8N, você está habilitado para fazer requisições para os recursos do Google Cloud. E é exatamente isso que acontece na sequência. O N8N faz uma aquisição do tipo post para a API do Google Cloud usando o token que foi permitido para ele usar. E depois, uma vez que ele fez essa chamada API, o FCM vai lá e envia a notificação para o dispositivo. Só qual que é a parte interessante do processo? Todo esse processo de obter o token lá do Google Cloud é feito de forma automática no N8N através da credencial de conta de serviço. Ele já tem isso pré-cadastrado, onde você só coloca alguns dados lá, ele faz toda essa chamada para obter o token. Então a gente pode ficar tranquilo em relação a isso. Vocês vão ver que é bem simples na prática.
