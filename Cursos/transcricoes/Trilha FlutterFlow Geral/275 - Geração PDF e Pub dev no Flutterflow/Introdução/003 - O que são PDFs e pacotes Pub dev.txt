Bom, então vamos começar conceituando o que é um PDF. PDF é a sigla para Portable Document Format. É um formato criado pela Adobe em 1992, ou seja, há mais de 30 anos, e ele foi criado para, como a própria descrição diz, proporcionar uma maneira fácil e confiável de apresentar e compartilhar documentos em qualquer software, hardware ou sistema operacional usado pela pessoa que exibe o documento, ok? Ou seja, é um formato versátil, um formato que qualquer pessoa, independente da plataforma que ela usa, consegue ler, consegue compartilhar, entender aquele documento. Então foi uma solução incrível pela Adobe para facilitar esse mercado. E quais são as alternativas para a criação de PDFs que existem hoje? Hoje existem várias ferramentas por aí. Eu separei duas, a CraftMyPDF e a Unview. Mas para que servem essas ferramentas? Basicamente, ao invés de você utilizar código para criar seu PDF, você vai lá e tem uma interface do estilo arrasta e solta. Você monta o seu PDF. o seu cabeçalho, a estrutura das tabelas, tudo mais, o layout, o design, e basicamente envia informação para uma API, e essa API consome os seus dados e gera o PDF. É lógico que é uma ferramenta muito simples, muito intuitiva de mexer. Eu já trabalhei com Craft My PDF e realmente é muito simples. Porém, se você olhar ali, tem o pricing, ou seja, é uma ferramenta paga. Você consegue criar PDFs gratuitos até um determinado volume, mas depois disso você tem que pagar para utilizar. Então imagina uma aplicação para ela escalar. Além dos custos com banco de dados, você também vai ter os custos com uma outra ferramenta de PDF. Então talvez no longo prazo isso não seja interessante. O interessante é que você tenha autonomia sobre essa geração de PDF para não ter custos relacionados a isso. E é exatamente isso que a gente vai ver aqui. Como criar esses PDFs diretamente no Flutter Flow para que você não precise pagar nada para ferramenta nenhuma. Beleza? Bom, o próximo conceito é o que são pacotes de bibliotecas. Se você já fez os cursos aqui da NoCode Startup, você já deve ter entendido que o Flutter, que é o framework que é utilizado no Flutter Flow, ele trabalha com a famosa árvore de widgets. Ou seja, tudo que aparece na tela para o usuário, na tela da sua aplicação, é um widget. Ou seja, ele compõe, aliás, ele é um conjunto de vários componentes. em formato de árvore. Então, nesse exemplo que a gente tem aqui na tela, a gente tem o app, que é um widget. Esse app se divide em três telas, que é a tela de login, catálogo, carrinho. E dentro desses widgets eu tenho mais níveis. Então, você vê que ele vai quebrando em vários níveis, no formato de uma árvore, ok? E o que é um widget, de fato? Um widget é cada elemento que você vê na tela. Um botão, um campo de texto, uma app bar, uma imagem, tudo pode ser considerado como um widget, beleza? E é o seguinte. O Flutter, que é o framework, ele tem vários widgets nativos, né? Porém, a comunidade de desenvolvedores também pode criar widgets novos para incorporar no Flutter. Essa incorporação, ela é feita através de pacotes. Então, a gente tem no próximo slide aqui, uma definição bem geral desse cenário. Esses pacotes, que são esses novos widgets, essas novas funcionalidades, eles podem ser acessados através do PubDev, que é o repositório oficial de pacotes do Flutter. Lá tem vários pacotes expandindo as funcionalidades que o Flutter possui. Um exemplo é o pacote PDF. Então, só para deixar bem claro, pacote é uma coisa, biblioteca é outra. Ou seja, eu posso ter várias bibliotecas dentro de um único pacote, como é o exemplo aqui do pacote PDF. Eu tenho a biblioteca PDF, propriamente dita, e eu tenho a biblioteca widgets. A biblioteca PDF é um pouco mais low level, ou seja, muito mais relacionada aos bits que vão ser gerados na aplicação. Já a biblioteca widgets é um pouco mais high level, ou seja, mais próximo do usuário. E é nessa biblioteca que a gente vai trabalhar. Ou seja, é lá que a gente vai definir quais são os widgets que vão gerar o nosso PDF. Ou seja, novos widgets que não tem inativamente no Flutter, que vão ser incorporados na nossa aplicação. através desse pacote, ok? E especificamente com essa biblioteca. E dentro das bibliotecas, a gente tem classes. O que são as classes? Imagine que você vai construir uma casa. Você começa pela planta. A classe é como se fosse a planta de uma casa. E os objetos, como se fosse uma implementação dessa classe. Então, imagine, eu tenho a planta da casa e a casa construída é como se fosse um objeto. Eu posso construir várias casas a partir daquela planta, ok? É uma analogia bem simples para você pegar o conceito de classe e objeto. Não se preocupem em aprender o que são construtores agora. A gente vai ver isso em detalhe, mas resumidamente, dentro de cada classe, a gente vai ter construtores, propriedades e métodos. E a gente vai trabalhar com esses caras. A gente vai manipular esses caras para construir o PDF exatamente do jeito que a gente quer. Então, resumindo é isso. O PubDev é onde a gente vai encontrar os pacotes. Cada pacote pode ser constituído por várias bibliotecas e cada biblioteca pode adicionar novas funcionalidades, ou seja, novos widgets no nosso Flutter. E outro conceito importante é o seguinte, cada pacote que você baixar lá no PubDev, ele vai ter um numerozinho na frente. O que é isso? É a versão do pacote. Então, basicamente, a gente tem... o nome do pacote, no caso o PDF. A gente tem a versão que é constituída por esses três dígitos, que é 3.10.8. E o que significa cada um deles? Você provavelmente já deve ter visto isso na hora de baixar algum software pela internet. Basicamente, esse último número representa quando esse número muda. Quer dizer que um erro foi identificado e corrigido. Quando esse segundo número muda, quer dizer que uma nova funcionalidade foi adicionada. E quando esse terceiro número muda, quer dizer que já não tem mais compatibilidade com a versão anterior. Então, se esse cara sai de 3 para 4, provavelmente as features que foram implementadas na versão 3 vão deixar de funcionar. E esse circunflexo basicamente informa ao teu gerenciador de dependência que ele pode aceitar qualquer versão que é compatível com essa versão maior aqui. Então... Se amanhã o pacote PDF for de 10 para 11, ele vai atualizar automaticamente, porque ainda é compatível com a versão 3. Se mudar para 4, aí não vai atualizar mais, porque aí deixa de ser compatível. E esse gerenciamento de dependências... é feito no Flutter ou no Flutter Flow, Flutter Flow é só uma implementação do Flutter, esse gerenciamento de dependência é feito através de um arquivo que chama pubspec. Você vai ver lá na telinha do Custom Code, eu só adiantei aqui para vocês, onde você coloca qual é o nome do pacote para que ele possa fazer o gerenciamento dessa dependência, ou seja, o teu código depende desse pacote. E por que eu preciso ter um gerenciador para isso? Porque imagina, o pacote PDF... Ele também depende de outros pacotes. E esses pacotes, por sua vez, dependem de outros. Então, imagina você ter que ficar correndo atrás de versão atualizada de cada pacote que depende. Isso é muito trabalhoso. Isso é inviável para o desenvolvedor. É por isso que tem um gerenciador de dependências no Flutter, que é o PubSpec. E o Flutter Flow incorpora isso direto na interface. Beleza? É muito mais fácil de trabalhar. Então, é isso. Vocês acabaram de ver o conceito de widgets. O porquê que a gente usa pacotes. Para que serve um pacote? Basicamente para incorporar novas funções à minha árvore de widgets e como entender o versionamento desses pacotes. O que esperar quando você ver um pacote e olha lá que ele mudou de versão. Então, bora para a prática conhecer o PubDev, que é o repositório de pacotes, como ele funciona, como entender a documentação e muito mais. Beleza? Te vejo na próxima aula.
