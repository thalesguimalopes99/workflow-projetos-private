Vamos entender agora um pouco sobre os bancos de dados relacionais e os não relacionais. Para a gente partir do zero, um banco de dados é uma coleção organizada de informações estruturadas. Então tem esse exemplo de uma tabela, geralmente ali no Excel, a gente tem bastante essa clareza do que é um banco de dados quando a gente tem as informações aqui organizadas por linhas e por colunas. Então aqui a gente tem o cliente, o nome do cliente, a idade, temos o valor do campo. Isso nada mais é. Que é uma forma de um banco de dados. E a gente fica bem claro do banco de dados relacional. Então aqui no banco de dados relacional. É quando a gente tem várias tabelas. E elas se relacionam entre si. Por exemplo aqui eu tenho o ID do livro. Que ele vai se conectar aqui com uma tabela. Que só vai ter os livros. Aqui eu vou ter o ID do pedido. Que vai se conectar com uma tabela. E vai ter só as vendas. Cada pedido vai ser uma venda. Então, por meio das chaves primárias e chaves estrangeiras, a gente consegue fazer a conexão entre as tabelas. E daí a gente tem uma modelagem do banco de dados. Se você quiser aprender mais sobre modelagem de banco de dados, depois a gente vai ter uma parte aqui no curso que a gente vai falar só sobre isso, tá? Pode ficar tranquilo que é bem legal. E lá eu me aprofundo bastante. Tanto tem a parte de modelagem em SQL e a modelagem no SQL. Então essa seria a forma da gente fazer os dados aí de tabelas com banco de dados relacionais. Como eu tinha falado, o Supabase usa banco de dados relacional. E também o Xeno tem essa parte aí do banco de dados relacional. No Firebase vai ser um pouquinho diferente. Em relação ao invés de ser tabelas, vão ser documentos e coleções. E como é que funciona isso, Castelo? Então uma tabela vai ser uma coleção, vai ser uma pastinha. Uma linha... Vai ser um documento. Um documento vai estar dentro da nossa pastinha, tá? Então, a gente vai ter as tabelas, que são as coleções. E as linhas, que são os documentos. Então, para deixar aqui mais claro, a gente tem aqui, ó. Por exemplo, vamos supor que a gente tenha as coleções, as nossas pastinhas. Cursos, alunos, professores e vendas. A gente tem as pastinhas, tá? E as pastinhas são como tabelas. Vamos supor que tem as tabelas dos alunos aqui, ó. A pastinha do aluno vai ter um documento. Cada documento vai ser um aluno. Então olha que legal, fica bem fácil da gente conseguir entender como é que funciona. Então aqui vai ter aluno, vai ter o id do aluno, o nome do aluno, a idade do aluno, o e-mail. E aí, esse formato aqui que a gente vai organizar dentro do documento, a gente fala que é o formato JSON, tá? Vai ser o formato com as chaves. Então aqui dentro da chave do documento aluno, a gente vai ter os campos e o valor para cada campo. É um formato bem flexível que fica bem fácil do computador entender. Então, nada mais é que dentro dessas coleções, a gente vai ter, dentro dessas pastinhas, vão ter os documentos. Esses documentos vão estar organizados nesse formato JSON. Então, aqui eu vou ter vários documentos que vão ser vários alunos. Aqui eu vou ter vários documentos que vão ser várias vendas diferentes. E daí a gente consegue organizar dessa forma aqui entre coleções e documentos. Pode ficar um pouquinho confuso, mas depois quando a gente for fazendo com nossos bancos de dados, vai ficando cada vez mais fácil e uma hora você vai estar preferindo fazer o banco de dados com o NoSQL. E para você ter uma ideia, temos grandes bancos de dados no mercado, como por exemplo o MongoDB, que é um dos maiores bancos de dados, o CautDB também, e o Firebase, que ele não é só um banco de dados no NoSQL, mas com um back-end, porque ele fornece todos aqueles serviços que eu já tinha comentado. Então em resumo, para a gente voltar ao que a gente já tinha falado lá na comparação dos back-ends, a gente tem o banco de dados relacional e o não relacional. Os relacionais são as tabelas, que elas vão se conectar entre si, é focado em relações, e o noSQL é um esquema mais dinâmico, flexível, a gente permite relação, menor foco, e também não é muito bom para consultas complexas. Mas você vai ver que o noSQL vai te deixar muito flexível para criar os bancos de dados. Então, mas essa que seria a grande diferença entre os dois.
