Agora que a gente já passou por toda a parte de design, vamos para a parte de inteligência e back-end. E para a gente começar, é importante ficar claro para você o que é uma arquitetura de sistemas e a diferença entre um front-end e um back-end. Então, quando a gente está construindo um software, um SaaS, a gente realmente tem duas partes. Uma é o front-end e também o back-end. O front-end vai ser toda a parte de design das telas, tudo onde o usuário vai interagir, o fluxo do usuário, as lógicas de negócio também. E no back-end vai ser todo o banco de dados, a segurança e autenticação, armazenamento de mídias, né? Para guardar fotos ou PDFs e também ações aí do servidor que vão acontecer sem alguma interação do front-end. Então é muito importante você entender que os dois vão andar juntos quando a gente está criando aplicativos ou softwares. E o Flutter Flow é uma ótima ferramenta e é focado para front-end, tá? Ele não tem a parte do back-end em conjunto. A gente tem que conectar com um serviço de back-end que vai fazer todas aquelas funções. E o Flutter Flow tem conexão nativa com o Firebase. e com Superbase e conexão via API com o Zenon, tá? O Faribase e Superbase são backends muito completos, mas eles são mais hardcode, então eles podem ser um pouco mais técnicos. E o Zenon é no code, então fica um pouco mais fácil a gente usar. E para você entender um pouco melhor como é que funciona... No Xeno e no Superbase vão ser bancos relacionais. São bancos parecidos com o que a gente vê no Excel, né? São aquelas tabelas que a gente consegue fazer conexão entre as tabelas. A gente tem esquemas definidos, eles são focados em fazer relações e é bom para fazer queries complexas e joins, tá? E no Firebase vai usar um esquema mais flexível de documentos e coleções. E ele não é muito bom para queries muito complexas, consultas complexas e joins. Só que o Firebase é muito bom porque ele consegue escalar e tem grandes empresas usando isso. Tanto o Firebase quanto o Superbase e o Zenon são ótimos back-ends para você escalar o seu aplicativo. Eles aguentam bastante volume de dados e são muito bons para você estruturar para o seu app. E quais são os principais diferenciais e aplicações? é bom para o Faribase é um banco não SQL flexível ele vai utilizar documentos e relações é um bem que mais técnico muitas funcionalidades integrações aí com o Google eu vou ter foi nasceu já junto integrado com o Google e tem uma relação muito próxima com a Google e o Faribase é do Google então tem muitas integrações prontas fáceis de usar entre o Flutter Flow e o Faribase por isso que tem maiores integrações para aplicações projetos que necessitem maiores flexibilidade no SQL integrações com o serviço Google né então a gente consegue ter acesso a muitos serviços da Google unindo aí o Paribasic Flutter Flow e aí a gente tem o Superbase que é um banco relacional postgrim então a gente consegue fazer essa conexão dos bancos de dados é um beckin de técnico também a gente consegue fazer a PES via SQL que é bem interessante é nativo para o Flutter Flow a gente não precisa da conexão via API a gente consegue fazer diretamente e também o diferencial dele é que é a open source ou seja tem código aberto para também a gente quiser tirar o Superbase da onde está rodando e conseguimos hospedar em nossa máquina local para aplicações projetos com bancos relacionais e um bom custo-benefício também temos o banco Zeno que é um banco post que a gente sempre tem no code API no code conexão via API com o Flutter Flow não é uma conexão ativa o diferencial do Zeno é que ele é no code e ele é muito bom para escalar o único problema dele é que ele é um pouquinho mais caro que deixa projetos iniciantes mais difíceis de começar com o Flutter Flow e com o Zeno mas ele é uma ótima escolha também por ele ser no code E aqui nesse curso a gente vai focar 100% em Supabase. O objetivo aqui vai ser explorar da melhor forma a conexão entre o Flutter Flow e o Supabase. Caso você queira aprender o Firebase, a gente tem outro curso especial apenas para isso. Aliás, a gente recomenda até que a pessoa aprenda Firebase no começo, porque é o que tem mais integrações com o Flutter Flow e o que acaba sendo mais fácil para se entender o Flutter Flow. Mas aqui no caso a gente vai usar o Supabase também que é um excelente back-end post com os bancos relacionais e também facilita bastante o aprendizado da modelagem de dados. E caso você não conheça o Supabase, bora trocar uma ideia sobre ele.
