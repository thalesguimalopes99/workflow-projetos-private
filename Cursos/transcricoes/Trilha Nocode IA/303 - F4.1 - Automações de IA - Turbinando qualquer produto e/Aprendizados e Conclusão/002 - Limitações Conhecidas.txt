Salve pessoal, nessa aula aqui eu quero comentar sobre algumas limitações desse nosso processo, desse aplicativo que a gente construiu, algumas formas da gente estar mitigando essas limitações também, para que vocês tomem consciência e a gente vai elevando o nível de conhecimento e conteúdo que a gente está passando aqui também. Então a primeira limitação que eu quero comentar com vocês, que não é bem uma limitação, é mais um entendimento da stack que a gente escolheu, e a gente escolheu aqui para fazer essas construções nessa nossa formação inicial, algumas partes das nossas fases, a gente utilizou o Google Sheets como uma das nossas bases de dados. A gente tem outros cursos que a gente vai estar utilizando o Supabase como uma base de dados, que é uma base de dados extremamente escalável e de fato para a gente utilizar em grandes aplicações em produção. O Google Sheets já não. O Google Sheets foi construído para ser uma planilha, então ele tem toda uma flexibilidade, porém ele não foi feito para ser utilizado de fato como uma base de dados. O software tem uma integração e a gente consegue fazer esse uso, porém é importante que a gente entenda algumas limitações. Então, uma das limitações, a gente já entendendo, é que o Google Sheets, de certa forma, ele é uma base de dados frágil. A gente não tem ali como que a gente, por exemplo, delimita qual tipo de dado vai para cada uma das colunas, o que é algo bastante comum em base de dados como um todo. Então, tem esses pontinhos aí que a gente precisa ter essa ciência. Além disso, a gente também tem que ter um conhecimento de que o Google Sheets tem um limite de requisições por minuto da API do Google Sheets. Então se a gente tem uma aplicação muito grande, fazer requisições o tempo inteiro para atualizar essa planilha, a gente pode ter uma quebra. E aqui no nosso caso, até vindo aqui para a tela do computador, para a gente relembrar, no momento que a gente fez a adição via Make aqui na nossa aplicação, a gente adicionou ali os dados da EduAI aqui e ficou faltando, obviamente, o nosso ID do software. Então isso é algo que o software atualiza dados em intervalos ou depois a gente ter uma interação mais direta no aplicativo do software mesmo. Então, essa não é necessariamente uma limitação, mas é algo que a gente precisa ter ciência, porque a gente não vai ter uma resposta imediata para o usuário no front-end. Algo que a gente poderia mitigar e utilizando, por exemplo, um Airtable como nossa base de dados, que é uma base de dados que tem uma integração mais redondinha com o software, que é uma base de dados que também já tem uma estruturação de dados. Então, é algo para a gente elevar um pouco o nível, caso faça sentido para vocês utilizar essa stack software. com alguma outra aplicação. A gente pode usar o Google Sheets por simplicidade, facilidade, para muitas coisas vai funcionar. Se a gente quer elevar um pouquinho o nível, o Artable vai ser uma excelente alternativa para utilizar como banco de dados do software. Então, até mesmo se eu fosse construir uma aplicação um pouquinho mais para colocar em produção mesmo, algo aí, colocar para usuários externos utilizarem, não fosse algo interno da minha empresa, algum planilho de gestão interna, eu já olharia para fazer um uso aí. do Airtable como base de dados, tendo em vista as limitações que a gente tem no Google Sheets. Beleza? Mas isso é algo muito simples. Airtable é outro banco de dados extremamente simples também. Ele foi feito para ser utilizado por pessoas não técnicas. Então, é tão simples quanto, eventualmente, o Google Sheets. Então, essa é a primeira limitação. A segunda limitação que eu quero comentar também é com relação, ainda com um pouco de relação aqui com o Google Sheets. O Google Sheets, ele não tem o storage dele, né? Então, a gente não consegue... armazenar arquivos, imagens aqui dentro do Google Sheets. A gente apenas coloca URLs de imagens aqui, por exemplo. E essa nossa imagem, quando a gente está gerando lá na OpenAI, a OpenAI gera a imagem, gera uma URL para a gente, porém essa URL é uma URL temporária. A OpenAI não vai ficar hospedando essa imagem lá no servidor dela para sempre imagens que a gente gera via API. Então até se eu clicar aqui, eu já arei essa imagem aqui. minha última aula há mais de duas horas atrás, até se eu clicar nessa imagem, para abrir a nossa imagem lá do nosso aplicativo que a gente construiu, eu já não tenho mais acesso a essa nossa imagem nessa URL. Porque as imagens geradas via API da OpenAI, elas ficam disponíveis aí, nesse momento que eu estou vendo, por duas horas para a gente ter acesso a elas. E aí depois disso, elas expiram para não ter acesso, para também a OpenAI não ficar gastando storage deles com essas imagens. Então, o correto é a gente pegar essas imagens, fazer o download dessa imagem, subir essas imagens em algum storage nosso, e aí sim a gente utilizar essa URL. Como eu disse, o Google Sheets não é um storage, a gente não consegue colocar imagens aqui e nem arquivos. Já, por exemplo, um Airtable da vida, a gente já conseguiria subir os arquivos dentro do Airtable, eles estariam armazenados dentro da estrutura, do storage, da infraestrutura do Airtable. A gente poderia subir isso também num Google Drive, por exemplo, ou também num Box da vida, enfim, a gente tem diversos ferramentas de armazenamento. E aí, ferramentas mais robustas, um AWS da vida para a gente fazer esse armazenamento de arquivos. Então, é mais esse pontinho também, que nesse nosso case aqui, a gente não fez nenhum processo de armazenamento dessa imagem, para a gente não estender em pontos que acho que não faria sentido para a gente estender aqui. Só aí, trazendo essa aula para deixar isso claro, uma forma que a gente poderia fazer isso é ou trocar toda a nossa estrutura de banco de dados aqui para a Artable e também armazenar nossas imagens e arquivos no Airtable, ou a gente colocar no meio do nosso processo de automação ali algum storage, seja um Google Drive, seja um Box, seja um Dropbox, seja enfim, um storage aí na AWS, WhatsApp da vida, existem diversos possíveis storage que a gente poderia estar utilizando. E aí aqui no Google Sheets a gente apenas indicaria o URL, estaria direcionando para aquele nosso storage, que ali sim é nosso, e aí a gente faz a gestão da forma como a gente quiser. A gente não vai perder essa imagem. Bacana? Então, queria criar essa aula aqui para trazer essas limitações conhecidas, coisas que não vi muito valor em estar adicionando nas aulas em si, mas vejo o valor de a gente estar comentando sobre isso para deixar claro algumas limitações do que a gente veio construindo aqui e também algumas formas de mitigar isso que não são nada complexas.
