Nesse módulo, nosso objetivo é focar nesse processo aqui de reg, onde a gente tem a nossa base de dados de conhecimento, fazemos o processo de retrieve augmented generation e a gente passa por esse processo todo de embedding dos nossos dados. Relembrando alguns conceitos rapidamente, embeddings nada mais são do que essas representações vetoriais dos elementos no qual o LLM busca criar por similaridade a esses vetores. Lembrando que esses vetores não é uma versão bidimensional, mas sim algo tridimensional. Então, a LLM busca colocar os elementos que estão sendo imputados para ela nesse espaço tridimensional, sempre buscando levar em consideração a similaridade para essa seleção de pontos nesse espaço. Isso é apenas importante para saber como curiosidade por debaixo do plano, como as coisas funcionam e como a LLM vai estar buscando informações análogas a algo que... a gente está enviando ou análogas às informações que ela já tem dentro da base de dados dela. Como base de dados vetorial, a gente tem alguns exemplos aí, como o Pinecone, acho que um dos principais nomes nesse mercado. A gente tem o Redis aí também, que tem uma base de dados vetorial, que é Quedrante, Milvus e o Supabase também possui aí a sua versão vetorial do banco de dados. Perfeito, então os dados são enviados para a LLM, passam por um processo de embedding nos modelos de embedding das LLMs e são armazenados nos bancos de dados vetoriais para que depois a gente consiga consumir essa informação. Essas informações são consumidas pelo tal do processo do Retrieve Augmented Generation, que nada mais é que esse processo de a gente melhorar os contextos da LLM para ela gerar respostas mais específicas para os nossos objetivos. insere dados na LLM, ela passa pelo processo de embedding, depois a gente tem esse dado à nossa disposição para a gente conseguir gerar respostas mais ricas. Então o processo como um todo basicamente ele passa de uma busca, essa busca a gente faz uma verificação, passa por um processo de embedding também, e aí a gente faz uma avaliação dentro da nossa base de dados vetoriais, porque agora a gente tem vetores, comparando vetores com vetores por similaridade, e aí a gente busca contexto extra. para essa nossa busca, basicamente. E aí a nossa pergunta mais busca é gerada aqui uma pergunta com o contexto, isso passa pelo LLM, o LLM com a pergunta mais o contexto tem mais informação para nos dar. uma resposta mais confiável e mais robusta. Então, de modo simplificado, RAG, processo de embeddings, esse, de modo geral, é o processo.
